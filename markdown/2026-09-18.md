## 补漏验证：又挖出 3 个真 bug（一处会爆栈）

上一轮 81 条全过，但圆点块 / 分割线·间距·高级 HTML / 颜色「跟随主题」/ 刷新后草稿恢复
这几块没覆盖。补了一轮 `_verify/sb-verify2.js`，第一遍就崩在 `RangeError: Maximum call
stack size exceeded`。

### 1. `stSet()` 允许标量顶掉对象（数据损坏）

兜底分支 `v = String(value)` 对**对象**也生效。把「整块的路径」
（`card.statusBar.blocks[0]`）当字段路径传进 `stSbClearColor` 时，整个块被写成 `''`。
修法：`typeof cur === 'object'` 一律拒绝写入。已确认全应用没有任何 UI 路径传对象路径
（`grep` 过所有 `stSet(` 调用形态 + 所有字段构建器，没有裸 `p` 当 path 的）。

### 2. `stSbLocate` / `stSbChain` 的 `list || 根列表` → 无限递归

递归时 `b.children` 是假值就把**根列表**又拿回来，原地转圈到爆栈。第 1 条是它的触发器。
修法：用「一个参数都不带」识别「从根找起」，递归进来 `list` 不是数组就当空列表；
再叠深度上限 40。**两条必须一起修**，单修一条只是把爆栈换成静默数据损坏。

### 3. 设完颜色「跟随主题」按钮不出现

`stAfterSet` 默认不重画属性面板（保光标），颜色那格只有整页重画才重建。
修法：新增 `stSbRefreshColorBtn()`，只替换颜色输入框的**兄弟节点**，
不碰输入框本身（`input[type=color]` 边拖边触发 `input`，换元素取色器会当场断）。

### 排查无限递归的手法（值得复用）

逐句复现**不复现**。最后是「**原样重跑失败的验证脚本** + 启动时把可疑函数换成带计数器的包装」
才抓到现场：

```js
stSbLocate = function (id, list, prefix) {
  window.__depth++;
  if (window.__depth > 25) throw new Error('DEPTH>25 listIsArray=' + Array.isArray(list) +
    ' blocks=' + JSON.stringify(dump()));
  try { return window.__origLocate(id, list, prefix); } finally { window.__depth--; }
};
```

要点：必须原样重跑（逐句复现丢掉的正是触发条件）；`Error.stackTraceLimit = 300`
否则看不到真正的调用方；报错信息里带**参数形状**比带栈更有用。

### 验证脚本自身的两个坑

- 属性面板字段数是在「选中间距块」时量的 → 永远是 0。测量必须在**目标块被选中时**做
- `stSbSel = ''`（漏了 `stEditor.`）→ 凭空造了个游离全局，页面状态一点没变。
  **赋值给错名字不会报错，只会静默什么都不做**，断言照样跑
- 页面弹 `confirm()` 的地方（换版式、覆盖别人的状态栏）必须挂
  `Page.javascriptDialogOpening` 自动应答，否则 `Runtime.evaluate` 一直挂着直到超时

## 功能：卡里已有状态栏时，解析它并编辑已有元素

用户原话：
> 如果卡内已经有状态栏界面，则尝试读取，并能够对已有元素进行编辑

### 之前

「状态栏界面」正则如果是**别人手写的**（`foreign`），结构注释（base64）不在，
读不回块列表 → 只能整段覆盖，等于让作者推倒重来。

### 现在：`stSbParseDoc()`

`foreign` 状态下多一个「🔍 解析卡里现有的状态栏」。剥 ```html 围栏 → DOMParser →
找外壳 → 逐个子元素翻译成块。

**核心原则：拆不动的地方原样留成「高级 HTML」块。** 宁可留一块看不懂的，也不能悄悄丢掉。

认得的（只看内联 `style` 的形状，不做真正的 CSS 计算）：
- `bar`：`overflow:hidden` 容器 + 内层宽度 `calc()`
- `dots`：`span[position:relative]` 的最后一个子 span 是 `overflow:hidden` + `calc()`
- `row`：`display:flex` 且每个子元素都带 `flex` / `flex-grow`
- `var`：自己没直接文字 + 有一个「整段就是一个宏」的直接子元素
- 分割线 / 间距 / 标题 / 文字：按高度、底色、加粗、`pre-wrap` 分

数值反解：`min`/`max` 从 `calc(({{…}} - 下限) / 跨度 * N)`；圆点个数 = 底排字符数；
字号按生成器写法反推（标题 `-2`、进度条表头 `+2`）。
颜色是主题那一套就不写进块（`stSbThemeColorOr`），继续跟主题走。

**故意不拆的三种**（拆了就是丢东西）：
1. 句子里带宏（`今天是 {{…}}，天气不错`）→ 留文字块。只有「整段就是一个宏」才算变量块
2. 带 `style` 的行内标签（`<b style="color:red">`）→ 高级块（文字块存纯文本，压下去颜色就没了）
3. `<table>` → 高级块。「光壳」规则原本会把表格拆散，所以收紧：只认 `div`/`span`，
   白名单里**不含 `width`/`height`**（那是内容不是布局脚手架）

### 新增 `statusBar.shellExtra`

外壳上**主题表达不了**的声明（阴影 / 渐变 / 毛玻璃）原样留着，追加在主题样式之后
（同属性后者胜，所以它盖住主题）。底色决定主题（精确匹配 10 分 / 明暗一致 4 分）。
`background` 只在是**纯色**时才交给主题，`linear-gradient()` 原样进 `shellExtra`。
顶栏给了可编辑文本框 + 「🧹 按主题重画外壳」。

### 解析报告 + 还原

解析完在状态区留报告：认出几个块 / 几个原样保留 / 外壳认作哪套主题 / 文字对不对得上。
「文字对得上」是自检：解析完立刻再生成一遍，比两边「看得见的文字」
（`stSbVisibleText`，去掉 `<style>` 内容、宏的两种写法先归一化）。

解析**立刻覆盖**卡里那条正则 —— 不覆盖的话 `sbOwn` 是 true 但 `state` 还是 `foreign`，
之后编辑会静默不写回，那更糟。原稿留在模块级 `stSbParseBackup`（**不进草稿**，
几百行 HTML 塞 localStorage 会把草稿挤爆），本次会话内可点「↩ 还原解析前的 HTML」。

### 顺手

- **画布上文字块里的宏也换成示例值**（`stSbSampleText`）。接管别人的卡时文字块里到处是宏，
  画布上显示 `{{format_message_variable::stat_data.日期}}` 看不出实际长什么样
- `stMvuLocate` 修掉和 `stSbLocate` 同一类隐患（`list || 根列表` 兜底）

### 验证：`_verify/sb-verify3.js` 99 条全过

最有分量的是 A 段**自往返**：6 个版式模板生成 → 抹掉结构注释变成「别人手写的」→ 解析回来，
块结构 / 主题 / 文字全一致且没有一块退化成高级块。
**生成器和解析器互为逆运算，任何一边改了而另一边没跟上，模板一跑就露馅。**

回归：`sb-verify.js` 81 / `sb-verify2.js` 62 / `smoke.js` 24 —— 合计 **266 条，全过**。

### 这一轮的 harness 教训

- 断言「容器行数 == N」前先确认**选择器真的命中**：`#st-sb-layers` 是我凭印象写的 id，
  容器上只有 class → `0 === 0` 会假通过（这次是 `0 === 12` 才被抓到）
- 断言 `.st-note` 拿到的是页面**第一个** `.st-note`（介绍文案），不是解析报告 ——
  给报告单独一个 class `st-sb-report`

## 第三段 · 「请尽可能按照原样解析」

用户原话：
> 请尽可能按照原样解析

上一轮的解析只还原**结构**，然后按生成器模板重画 —— 作者卡里的细节全被主题默认值顶掉：
轨道深紫变半透明灰、圆点间距 9px 变 4px、文字发光/字距/内边距没了、分组左列 `flex:2` 变等宽、
本来没外框的状态栏被硬套上主题盒子。

### 核心做法：拿生成器产物当基准做差集

```
原稿元素的内联 style  −  生成器给同一个块写出来的 style  =  必须原样保住的声明
```

`stSbOwnMaps(b, themeId)` 把块生成一遍、`DOMParser` 读回来，拿到 outer / inner / fill 三层的
style map；`stSbExtraOf(actual, own)` 做差；`stSbKeepStyle()` 记到块上。

**为什么这么绕：这样解析器和生成器永远共用一套判据。** 以后改生成器（加条 border、换默认色），
差集自动就对得上，不用两边同步维护一张白名单。

- 分层字段：`extra`（最外层）/ `extraInner`（「底」：bar 轨道、dots 装圆点那层）/
  `extraFill`（「亮」：bar 填充、dots 亮点层）/ `wrapExtra`（分组里的列容器）
- `track` 单独拎成正经字段（面板上能改），只在值 ≠ `ST_SB_BAR_TRACK_DEFAULT` 时才存 ——
  否则每次自往返都往 extraInner 里塞一条我们自己写出来的声明
- 比较前 `stSbNormCss` 去空白 + 小写，免得 `margin:3px 0` 和 `margin: 3px  0` 被当成两回事
- 生成器**已经写过**的声明不记 —— 记了就是同属性写两遍，用户之后改字号/颜色就改不动了

### 外壳：`shellOff`

生成器无条件写 11 条外壳属性（`ST_SB_SHELL_PROPS`）。原稿没写哪条 → 记进 `shellOff` →
生成时跳过。装满 11 条 = 外壳退化成裸 div。顶栏「▢ 不套主题外框」按钮整组开关。

### 三个颜色字段的来历

手写状态栏里「显示名」「没点亮那排圆点」「右边那个数值」是**三处独立颜色**，
只留一个 `color` 必然有两处被顶掉 → `labelColor` / `emptyColor` / `valueColor`。
`var` 不要 `valueColor`（它的 `color` 本来就是数值色）。

### 修掉的 4 个真 bug

| 症状 | 根因 |
|---|---|
| 解析自己的产物时标题被读成「加粗文字块」、字号缩水 | 给标题加了 `white-space:pre-wrap`（保 `<br>`），而 title 判据是「加粗 + 没有 pre-wrap」。补生成器签名 `margin:0 0 6px` + `line-height:1.4` |
| 原稿的 `<br>` 解析后消失 | `textContent` 对 `<br>` 什么都不返回。先把 `<br>` 换哨兵，压完空白再换回 `\n` |
| 原稿带 `white-space:normal` 时换行又被压掉 | 差集把 `white-space:normal` 记进 `extra` 追加在 `pre-wrap` 之后（后者胜）。文字/标题块的 `white-space` 一律不许进 extra |
| 圆点点亮色和数值色被绑成一个 | `b.color` 同时喂亮点层和数值 span → 拆出 `valueColor` |

## 第五段 · 运行时镜像：「实际游玩时怎么解析，编辑器就怎么解析」

用户原话：
> 原样解析指，在实际游玩中如何被mvu框架解析，编辑器就如何解析

上一轮的「按原样」只做到「解析出来的东西别丢」。这一轮把它顶到真正的准绳上。

### 推翻一条旧结论

文档里写着「酒馆用沙盒 iframe 渲染，head 里的样式会被剥掉，所以只能内联」。**错的。**

酒馆助手判定「这段代码要渲染成界面」的条件只有两条：
① 代码在 ```` ``` ```` 围栏里；② 代码里**同时有 `<body>` 和 `</body>`**。
满足之后它被当作**一个独立网页塞进 iframe** —— `<style>` / `<script>` / 外链资源**全都可用**。
`vw` / `vh` 以 iframe 为准（只有 `min-height:*vh` 被官方特判为以视口为准）。
生成器不用 class 是为了「块自带长相、不依赖外部定义」，不是绕过限制。

### 做了什么

1. **按同一套规则找块**（`stSbFences` / `stSbRuntimeInfo`）：合格围栏块优先；
   不合格的（有围栏没 `<body>` / 连围栏都没有）**照样解析**，报告里 🚫 说明
   「玩家那边看不到，只会看到源码」，**写回时补成合格包装**（顺手修好）。
   围栏**外**的原文存 `statusBar.pre` / `post`，逐字节拼回去，面板上有 textarea 能改。
2. **base64 结构注释移进 `<body>` 里面**：注释不是元素，不影响那两条判定、也不多出块。
3. **`<head>` 里的 `<style>` / `<link>` 捞出来当高级块**，排在块列表最前（样式块靠先后定胜负）。
4. **class 保原样**：`clsMap` 按 7 层 + 外壳 `shellCls`，写回照贴。
5. **按属性粒度抑制内联**（`clsOwn` + `stSbLook`）：内联永远赢过 class，生成器照主题
   写一串内联，作者的 `<style>` 就白写了。改成「只写原稿内联里真正写过的那几个属性」。
6. **`white-space:pre-wrap` 收敛**（`stSbPreWrap`）：带 class 的层只在文字里确实有换行时才写。
7. **真机预览 iframe + 运行时体检**：画布用的是编辑器的 CSS，回答不了「玩家那边什么样」。
   预览用同一套包装、`sandbox` 故意不给 `allow-same-origin`、240ms 防抖。
8. **外壳识别放宽成三条判据**；`stSbFindDeep` 收紧成「只在独苗路径才递归」。

### 修掉的 7 个真 bug

| 症状 | 根因 |
|---|---|
| 接管后结构注释丢了 → 立刻判 `foreign`、拒绝写回 | 重构 `stSbDocHtmlOf` 时弄丢了。补 `stSbMarkOf`，放进 `<body>` 里 |
| class 稿整张面板被判成「没有外壳」，内容全错位 | 外壳识别只看内联样式，而 class 稿的样式全在 `<head><style>` 里 |
| 有 class 的面板只认出 2 个块，其余全丢 | `stSbFindDeep` 太贪心，一层里多个元素时也往下钻，把整张面板误认成里面那行圆点块 |
| class 保住了但作者 CSS 里那条颜色还是被盖掉 | `clsBare` 按「层」判，粒度太粗。`<span class="hp-k" style="font-size:13px">` 整层被放过 |
| 带 class 的标题凭空多出一条 `pre-wrap` | 抑制过头。改成只在文字里确实有换行时才写 |
| 改了围栏外原文，运行时体检栏不刷新 | `stSbPaintPreview` 里「文档没变就 return」排在刷体检之前 |
| `style=""` 空属性破坏逐字节自往返 | 被 `stSbLook` 全滤掉后没声明了。补 `stSbStyleAttr`：空串整个不写 |

### 这一轮踩的坑

- **`sandbox` 不给 `allow-same-origin` 的 iframe 是 OOPIF，父页面够不着**。
  预览 iframe 故意不带 `allow-same-origin`（跟运行时一致），于是 `Page.getFrameTree`
  里根本没有它、`contentDocument` 是 `null`。得开
  `Target.setAutoAttach({autoAttach:true, flatten:true})` + 监听 `Target.attachedToTarget`
  收下子 `sessionId`，`Runtime.evaluate` 带上它才进得去
- **逐元素比对要跳过 `<style>` / `<script>`**，不只是 `<br>`：原稿写在 `<head>` 里的
  `<style>`，产物把它搬成了 body 里的高级块，CSS 全文档生效、位置不影响渲染，
  但元素表从那一格起全部错位（症状：`tag: DIV ≠ STYLE` 刷屏）
- **同一份断言不能套在所有 fixture 上** —— 断言要按稿子分档（`maxRaw`），
  写成全局「必须为 0」就是假报警
- **一个循环里既解析又导航会互相顶掉页面**：先导航到对照页之后再解析下一份，
  编辑器页面已经没了（`stSbParseDoc is not defined`）。拆成两段循环
- **`clsOwn` 这类「只在另一个字段非空时才被读」的字段，清理可以省** ——
  丢 class 时不用管同一层的 `clsOwn`（class 一空它就是死数据），
  但要在代码里写清这层依赖，不然下次有人改 `stSbLook` 就会踩

## 第六段 · 自由摆放：块能随手挪，1px 也能挪

用户原话：
> 保证当前能够让状态栏的块【原样解析指，在实际游玩中如何被mvu框架解析，编辑器就如何解析】的同时，
> 能够自由拖动，随意的更换位置（甚至可以只挪动几个像素那种）

难点全在**「同时」**上：第五段刚把「产物逐字节 / 逐像素对照」做成回归线，
这一轮要往产物里塞新东西，就得保证**没挪过的块一个字节都不多**。

### 偏移写成什么

```css
position: relative; left: Xpx; top: Ypx;
```

**相对定位，不是绝对定位** —— 绝对定位脱流，运行时那边后面的块整个塌上来，
那就不是「把这块挪一点」而是把整张排版砸了。

**两个偏移都是 0 时一条声明都不写**（`stSbOffCss` 返回空串），单条为 0 时那条也不写。
这条是硬要求：`sb-keep-compare.js` 那套逐像素对照的前提就是
「没动过的东西不许出现在产物里」。

### 两套手势互斥

「拖块换顺序」和「把块挪 3px」用同一套手势做不出来，所以做成开关
（`stEditor.sbFree`，默认**开**，跟着草稿存）：

| | 自由摆放：开 | 自由摆放：关 |
|---|---|---|
| 拖动 | 指针事件（`stSbPtrDown/Move/Up`）→ `offX` / `offY` | HTML5 DnD 换顺序 |
| `draggable` | `false`（主动让位） | `true` |

两道闸都留着的话，拖一下会「既挪位置又换顺序」。所以 `stSbDragStart` 在自由摆放开着时
**主动 `preventDefault()` 并直接返回**，不记 `stSbDragId`。

**为什么不用 DnD 做挪位置**：HTML5 拖放拿不到连续位移 —— `drag` 事件只给屏幕坐标，
`drop` 之后就失联了，做不出「跟手挪」和「松手前就实时看到结果」。

| 细节 | 值 | 为什么 |
|---|---|---|
| 起步阈值 | 3px | 低于它只当点击选中，手抖不会把块弄歪 |
| 吸附 | 按住 Shift → 8px 网格 | 想对齐时用 |
| 方向键 | 1px；Shift+方向键 → 10px | 像素级微调 |
| 范围 | ±800（`ST_SB_OFF_MAX`） | 防手滑把块甩到十万八千里外 |
| 指针捕获 | `setPointerCapture` | 拖到画布外面也不丢 |
| 实时反馈 | `stSbPtrPaint` 只改这一个元素 | 不重画画布，拖起来才跟手 |
| 落库时机 | 松手（`stSbPtrUp` → `stSbAfterOff`） | 拖动过程中不写 localStorage、不重写正则 |

`stSbPaintCanvas` / `stRerender` 会**记住并还原画布内部的 `scrollTop` / `scrollLeft`**，
否则每挪一下就弹回顶上。

### 解析别人的卡：`left` / `top` 读得回来，两个边界不碰

`stSbReadOffset` 只认 **`position` 恰好是 `relative`** 且 `left`/`top` 是 `px` 的元素。

- **`static` 上的 `left` 是无效的** —— 读成偏移等于我们凭空补一句 `position:relative`，
  把原本不起作用的声明**变得起作用**。那是改人家的稿。原样进 `extra` 带走。
- **`absolute` / `fixed` 是脱流写法**，是人家自己的排版手法（悬浮角标之类），
  也不能当偏移读。

读回来的偏移排在 `stSbOwnMaps` 差集**之前**，否则同一句 `left:8px` 会既进 `offX` 又进 `extra`。

**「纯定位壳」要拆。** `<div style="position:relative;left:8px"><table>…</table></div>`
这种壳什么结构都不像，会被兜底成高级 HTML 块；下一轮生成时块自己又写一次，
壳 + 块两层 → 再解析偏移翻倍（8 → 16），**越存越歪**。
`stSbOffOnlyWrapper` 认出来就拆壳、把偏移加到里面那个块上。

⚠ 它必须排在 `stSbParseEl` 的**兜底之前**、**所有结构识别之后**。放最前面会压过结构识别 ——
裹着一条轨道的定位壳本该被认成进度条。

### 这一轮踩的坑

- **「纯定位壳」拆早了，把进度条拆成了高级 HTML 块**。`stSbOffOnlyWrapper` 一开始插在
  `stSbParseEl` 第 0 步（结构识别之前）。挪到**第 8 步（兜底之前）**
- **进了 OOPIF 之后「求值成功」不等于「文档就绪」**。改 `srcdoc` 会让 iframe 整篇重载，
  新文档还没解析完时 `document.body` 是 `null`，求值照样返回（拿到空 body）——
  而 `frameEval` 只在**抛异常**时重试，返回 `null` 它当成正经答案。症状是
  「真机预览里那块也挪了」随机挂、单独跑又过（`sb-verify6` 的 H 段栽在这）。
  **改成轮询**：`for` 循环里 `sleep(200)` + `frameEval(...).catch(() => null)`，
  拿到目标状态才 `break`；表达式本身也写防御一点（`document.body ? … : null`）
- **旧断言的前提可能被新功能改掉，那不是回归**。`sb-verify2.js` 的
  「分割线没有多余的文本框」量的是 `.st-sb-insp` 里的 number / text 输入框数，
  而自由摆放给**每种块**都加了 X / Y 两格（分割线当然也能往下挪 3px）→ 0 变 2。
  断言改成 `:not([id$="-offx"]):not([id$="-offy"])` 排除掉。**看到失败先想前提，
  别急着改产品**

### 验证：八套 554 条全绿

`sb-verify.js` 84 / `sb-verify2.js` 62 / `sb-verify3.js` 99 / `sb-verify4.js` 99 /
`sb-verify5.js` 62 / **`sb-verify6.js` 92（新）** / `smoke.js` 24 / `sb-keep-compare.js` 32。

`sb-keep-compare.js` 保持 **32 / 0** —— 两份手写稿仍然像素级逐字节相同。
**它是这一轮的前提**：那条「零偏移零字节」只要破了，逐像素对照立刻变红。

`sb-verify6.js` 的 C 段与 H 段是核心证据：**C 证明能随手挪**（合成 `PointerEvent` 真拖一遍，
3px 阈值、拖动**过程中**就实时跟手、松手才落库），**H 证明挪了之后「按运行时规则解析」
那套一个字都没坏**（产物仍满足运行时两条判定、重新生成逐字节相同、真机预览里那块也真的挪了）。

## 第七段 · 调整大小：拖把手改尺寸，且仍然是「零尺寸零字节」

用户原话：
> 在此基础上，让已有块可以被调整大小

上一轮刚把「自由摆放」塞进产物、还保住了逐字节 / 逐像素对照，这一轮要在同一个产物里
再加一对字段 —— **「中性值必须一条声明都不产出」这条铁律第一次撞上了既有的产物**。

### 数据与生成

`SbBlock` 多两个字段：`w` / `h`（px，**0 = 自适应，不写**）。生成成
`width:Npx;height:Npx`，单条为 0 时只写另一条，两条都是 0 时 `stSbSizeCss` 返回空串。

⚠ **`space` 块的高不走 `h`，走它本来就有的 `height` 字段**（那个字段在它身上本来就是
「高度」的意思，多开一个只会让两个字段打架）。差异收在 `stSbSizeKeys(b)` 一处。

### 画布上的挂载点：偏移和尺寸不一样

| | 偏移 `offX`/`offY` | 尺寸 `w`/`h` |
|---|---|---|
| 写进卡里 / 真机预览 | 块自己身上 | 块自己身上 |
| 编辑器画布 | 挂外层 `.st-sb-hit` 命中框 | **也写在块自己身上** |

偏移挂命中框，是因为命中框就是拖动时跟手挪的那个元素。尺寸**不能照抄** ——
命中框是自动宽度的块级元素，`width` 写它身上块不会跟着变，改了个寂寞。
所以尺寸两边都写块自己，命中框另补 `width:fit-content` 把轮廓贴回块上。

这也是 `stSbBlockHtml` 那个 `noOff` 参数**管不到尺寸**的原因（`sz` 不受 `noOff` 影响）。

### 八向把手

`ST_SB_HANDLES = nw/n/ne/e/se/s/sw/w`，**只在选中的那一块上渲染** ——
每块八个把手、6 个块就是 48 个小方块，指针不知道抓哪个。
`e`/`w` 只动宽、`n`/`s` 只动高、四角一起动。

- 把手是 `.st-sb-hit` 的绝对定位子元素，`margin:-5px 0 0 -5px` 把中心对到角 / 边中点
- 有把手时徽章往右让一格（`.st-sb-hit.st-sb-hh > .st-sb-badge { left: 11px }`）——
  左上角那个把手正好压在徽章头上
- 复古皮肤跟着有（`.st-sb-h` 方角 + 银灰 + `#000080` 高亮）

### 拖动：按**内容盒**算，不是边框盒

`stSbMeasureEl(el, axis)` = 边框盒 − padding − border。因为写出去的 `width` 就是内容盒宽度，
拿 `getBoundingClientRect().width` 当起点的话，块有 padding 时**第一次拖会跳一下**。

**西 / 北边拖动时位置跟着走**：拖 `w` 往右 20px，宽少 20、`offX` 加 20。
`stSbResizeCalc` 在**夹紧之后从夹紧后的 w/h 反推**位置 —— 先算位置再夹的话，
拖到下限以下块会一边缩一边继续往右跑。

| 细节 | 值 |
|---|---|
| 起步阈值 | 2px |
| 吸附 | 按住 Shift → 8px 网格 |
| 下限 / 上限 | 8px（拖动地板）/ 2000px |
| 实时反馈 | `stSbResizePaint` 只动这一个块 + 它的命中框 |
| 落库时机 | 松手 `stSbResizeCommit` → **只写这次真正动过的那几个轴** |

### `Alt` + 方向键

`方向键` 挪位置 1px / `Shift` 10px；`Alt` 改尺寸 1px / `Alt+Shift` 10px。
一次按键只碰一个轴。**没设过尺寸时先量出当前大小当起点**，不然 `0 → 1` 会把块缩成 1px 宽。

### 解析：判据是「生成器基线」

`stSbReadSize` 只认 `px`（`%` / `calc()` / `em` 原样进 `extra` 带走），而且读之前先跟
`stSbSizeBaseline(b, themeId)` 比一遍 —— 把 `w`/`h` 清成 0 生成一遍，看生成器**本来会写什么**。

**不这么干就会踩：** 分割线自己写着 `height:1px`，那是**生成器写的**，不是用户设的。
不比基线就被读成「用户把高度设成 1px」，下一轮多写一条、差集还把原来那条抄进 `extra` ——
**一条声明变两条**，逐字节对照当场红（`sb-keep-compare` 与 `sb-verify4` 就是这么红的）。

配套两处：
- `stSbSizeNum` 下限**从 8 改成 1**（手写稿里真有 `height:1px`，夹到 8 就是改人家的稿；
  8 只当**拖动**地板）
- `divider` 分支在 `h` 非 0 时不再写生成器那句 `height:1px`

### 这一轮踩的坑

- **给块加字段会让旧断言的前提过时，而失败信息完全指不到真正的原因**。加 `w`/`h` 之后红了三处：
  ① `sb-verify2` 的「分割线没有多余的文本框」数出来 2 —— 每种块都多了 W / H 两格，
  断言得排除；② `sb-verify4` 的「保住的块数 ≥5」变 4 —— 加粗分割线的 `height:2px`
  从「原样保留」**升级**成了正经字段 `h`，是行为变好不是回归；③ `sb-verify6` 的
  「画布顶上有两个按钮」变 3 —— 多了「⤡ 尺寸复原」。**看到失败先想前提，别急着改产品**
- **`smoke.js` 的「产物里有进度条宏」约 20% 随机红** —— 见下面单独一段，是个漂亮陷阱

### 验证：九套 658 条全绿

`sb-verify.js` 84 / `sb-verify2.js` 62 / `sb-verify3.js` 99 / `sb-verify4.js` **101** /
`sb-verify5.js` 62 / `sb-verify6.js` **93** / **`sb-verify7.js` 100（新）** /
`smoke.js` **25** / `sb-keep-compare.js` 32。

`sb-keep-compare.js` 保持 **32 / 0** —— 两份手写稿仍然像素级逐字节相同。

`sb-verify7.js` 的 **J 段是这一轮的守门员**：**画布上量到的宽 == 真机预览里量到的宽**
（内容盒对内容盒）。画布和真机预览是两套 CSS 环境，只要有一边把 `width` 写错了地方

## 第八段 · 修掉验证体系里一个藏了一整轮的竞态（CDP 对话框）

`smoke.js` 的「产物里有进度条宏」一直以约 **20%** 的概率随机红，单跑又不复现。
连跑 12 次挂 2 次、20 次挂 4 次，稳定复现。

### 根因

`stSbApplyTemplate()` 在画布上已有块时会 `confirm()` 一句，而套件靠
`Page.javascriptDialogOpening` 自动应答。**CDP 那条路不可靠** —— 实测错误是：

```
open:confirm   ERR:{"code":-32602,"message":"No dialog is showing"}
```

事件收到了，但等我们的「点确定」指令到达浏览器时，**那个对话框已经被 Chrome 自己撤掉了**，
于是 `confirm()` 静默返回 `false`，模板根本没套上。

### 为什么找了一整轮

1. 那个错误被一个空的 `.catch(() => {})` 吞了 —— **错误必须留痕**。
2. 失败现场极具误导性：红的是「产物里有进度条宏」，但真正发生的事是「模板没套上」。
3. 更巧的是**块数仍然是 3** —— 装 MVU 时会播种一套「简约数值行」（`stSbDefaultBlocks`
   在变量树还空着时退回 `stSbTplBlocks('simple')`），也是 3 块，所以「块数 3」那条断言照样过。
   光看数字完全看不出差别，**必须把块类型和路径摊开打出来**。
4. 加任何一次 `Runtime.evaluate` 往返都会把竞态盖掉 —— 第一次写诊断脚本时加了两次
   `ev()`，20 轮全绿，反而更难抓。**抓时序问题不能动往返次数**。

### 修法

1. 9 个套件统一改成 `Page.addScriptToEvaluateOnNewDocument` 往页里装 `confirm` 同步桩
   （记下调用、返回 `true`）。「点确定」完全同步发生，跟 CDP 时序无关，刷新之后桩也还在。
2. CDP 的 `Page.javascriptDialogOpening` 只当保底，且 **`.catch` 不再空着**。
3. `sb-verify.js` / `sb-verify4.js` / `sb-verify5.js` 里那三条**断言「问过没有」**的，

### 从回复里抠 JSON（`stAiJsonOf`）

### 开场白（开场白页）

1. `enabled === false` 跳过（除非勾了「把已停用的也算进去」）
2. `position === Outlet` 跳过 —— 运行时它也不插入正文
3. 正文为空的跳过
4. 按位置分组：`↑Char → ↓Char → ↑AT → ↓AT → @D → ↑EM → ↓EM`
5. **`@D` 组内按 `depth` 从大到小** —— depth 是「插到倒数第几条消息之前」，
   数字越大离最后一条越远，排得越靠前
6. 同深度再按 `order`，最后按原始下标（稳定排序）

排好的顺序原样拼进提示词，面板上也能展开看。开场时对话里只有这一条开场白，

### 面板状态为什么要单独存

`stRerender()` 会把整个 pane 的 innerHTML 重建一遍，输入框的值**必须从状态里读回来**，
否则用户敲一半就没了。所以 `stAiUi` 是唯一真相，并且分了三种写法：

| 函数 | 什么时候用 |
|---|---|
| `stAiUiSet(k, v)` | 输入框 `oninput` —— **只写状态不重画**，重画会把光标顶掉 |
| `stAiUiSetR(k, v)` | 会让布局变样的控件（勾「包含停用」要重排注入预览） |
| `stAiRepaint()` | 写状态 + `stRerender()`。chip 点击、换来源、换协议都走它 |
| `stAiRefreshCfgStatus()` | 只刷状态行 —— 模型名是一个字一个字敲的 |

`<details>` 的展开状态也记在 `stAiUi`（`exOpen` / `grOpen` / `grShowInject`），
靠 `ontoggle` 写回 —— `stRerender` 只恢复 `.st-entry` 的 open，管不到它。

## 第十段 · 世界书单条改写：只改指定的那一条，可选参考别的条目

用户原话：
> 要求能对指定的世界书条目单独进行ai扩写改编（可选是否参考其他世界书条目）

上一段刚做完「批量扩写」（生成新条目追加到末尾），这一段要的是**原地改某一条**。
两件事的参数不一样，所以状态也另开了一组（`ex*` / `en*`）—— 混用一套的话，
用户从「新增 3 条」切到「改写这一条」，会发现条数设置被莫名其妙带过来。

### 面板挂在哪

`stEntryHtml` 里，`.st-entry-body` 的**最上面**（在备注 / 关键词这些字段之前）。
每条都有自己的 `<details class="st-ai-box st-ai-inline">`。

⚠ **收着的时候一条参数都不渲染**：世界书动辄几十条，每条都铺开一整套
（12 个要求 chip + 14 个氛围 chip + 7 个格式 chip —— ⚠ **这里的 12 是当时记错的数，
实为 14，已在 09-20 第十四轮改正**），光是按钮就上百个，
而 `stRerender()` 每次都要整页重建一遍。所以 body 只在 `enOpenId === e.id` 时才生成。

展开状态靠 `ontoggle` 写回。⚠ `<details>` 的 toggle 事件是**异步排队**的
（「queue a details toggle event task」），不是点击时同步触发 —— 所以：
① 处理函数要**幂等**（新渲染出来的 `<details open>` 也会补一个 toggle 回来，
两次都判一遍就不会打转）；② 验证套件点完 summary 要 `sleep` 一下再断言。

### 状态按 id 记，不按下标

`enOpenId` / `enPreview.id` / `enErrId` / `enMsgId` 全部存条目的 **uuid**。
条目上移 / 下移 / 删除之后下标会漂，用下标记状态会让「展开的」和「报错的」跳到别人身上。

配套：`stAiEntryRun(i)` 先记下 id，`await` 回来**按 id 重新找一遍**再写 ——
生成期间用户完全可能把这一条删了。找不到就给「这一条已经不在世界书里了」。

### 「参考其他条目」是三层过滤（`stAiEntryRefRows`）

1. 排除自己
2. 排除空壳（没正文也没关键词 —— 参考了等于没参考，还白占额度）
3. 按范围：`仅启用` / `全部` / `同分组`

⚠ `同分组` 在条目没有 `group` 时**静默退回「仅启用」**（`stAiEntryRefScope`），
chip 也不渲染 —— 不能给用户一个永远参考不到东西的选项。

喂给模型的是「备注 + 关键词 + 位置 + 正文前 200 字」，不是整条整条地喂。
被改的那一条才是主角，别的只负责「别写重、别写串」。

### 套用：两种

- **替换本条**：勾了「只改正文」就只写 `content`；没勾就 `content` / `keys` /
  `secondaryKeys` / `constant` / `position` / `depth` / `order` 全按模型的来
- **追加为新条目**：插在 `i + 1`，**必须换新 id**（两条共用一个 id 的话
  `enOpenId` 会同时匹配上两块面板）

⚠ **不勾「只改正文」也要防空值覆盖**：模型给空 `keys` / 空 `comment` 就保留原来的。
它偷懒给个空数组，不该被当成「用户想清空」。

### 回复形状：单对象，但三种包装都认

system 里明说「**只输出这一个对象，不要包成数组**」，但模型习惯性包一层，
所以 `[{…}]` / `{entry:{…}}` / `{entries:[{…}]}` 三种都拆开认。

### 这一轮踩的坑

- **氛围 / 格式 chip 点了没反应**（真 bug）：复用了批量那套回调，而它们**把键名写死了**
  —— `stAiMoodPick` 只认 `exMood` / `grMood`，`stAiFormatPick` 只写 `exFormat`。

## 第十一段 · 「第一段」+ 提示词结构预览

用户原话：
> 在主页的【ai对话】与【角色卡编辑】的【ai助手】里都添加【第一段】选项，让用户能够自行输入，
> 要求处于发送给模型的第一段，并为【角色卡编辑】的【ai助手】，以及世界书的全局ai扩写，
> 与独立条目的ai改写都添加【提示词结构预览】

### 「第一段」：一句话要落在两个完全不同的调用链上

主页的 AI 对话走 `buildRequestPlan()`（那里要照顾酒馆模式的槽位拼装），
编写器的三个功能面板走 `stAiChat([...])`（那里是手拼的三条消息）。
两条链路的代码离得很远，所以做法是**各自在自己的出口插一次，而不是共用一个函数**。

| | 插在哪 | 关键点 |
|---|---|---|
| AI 对话 | `buildRequestPlan()` 里，**两条 `return` 之前** | 非酒馆分支和酒馆分支都能生效；酒馆预览靠 `kind:'first'` 单独标色 |
| 编写器 | `stAiPlanMessages(plan)` —— 三个面板共用的唯一出口 | 第一段 → system → user |

### 为什么角色必须是 `system`

这是这一轮唯一一个**非它不可**的设计点：

- OpenAI 兼容：`messages[0]` 是 system，模型最先读到的就是它
- Anthropic：`messages` 必须以 `user` 开头、`system` 会被 `stAiSplitSystem` 提到顶层字段；
  如果把第一段写成 `user` 塞在最前面，就变成「先说话、再给指令」，
  而且 `stAiMergeRoles` 还可能把它跟后面的 user 合并

`system` 是**两条协议下都能排在最前面的唯一写法**。验证套件两头都断言了：
OpenAI 看 `body.messages[0]`，Anthropic 看 `body.system.indexOf(SEG) === 0`。

### 空着 = 一条都不发

跟状态栏那套「零值零字节」同一条铁律。`stAiPlanMessages` 里 `if (seg)` 才 push，
`buildRequestPlan` 里靠 `add()` 自己跳过空串。没填过的用户，产物一个字节都不变。

⚠ 它**不受**「系统提示词」和「酒馆模式」两个开关影响 —— 那两个开关管的是程序拼的那条 system。
验证里专门有一条：关掉系统提示词之后第一段仍然在 `messages[0]`。

### 宏的两种语义

- **AI 对话**：跟紧挨着的系统提示词一样走 `applyUserMacros`，`{{user}}` / `{{char}}` 都换
- **编写器**：只换 `{{char}}`（换成当前角色卡的名字）。编写器没有「用户昵称」这个概念，
  `{{user}}` 原样留着比替换成「你」更诚实

同一页里两种语义确实有点别扭，但两边各自的邻居是什么样，它就跟着什么样 —— 这个理由比强行统一更站得住。

### 提示词结构预览

四处：AI 助手页（骨架）、世界书批量扩写、单条改写、开场白（后三处是真实内容）。

⚠ **展开状态故意不进 `stAiUi`**。这一条是刻意的：存进状态就意味着每次 toggle 都要
`stRerender()` 重建整个 pane，滚动位置当场丢掉。而这几个 plan 纯粹是字符串拼接
（`stAiExpandPlan` 只读 `stAiUi`，`stAiBookBrief(60)` 有上限），算一遍很便宜 ——
不值得为它换一次重画。有一条断言盯这个：「展开预览不会改动持久化的面板参数」。

预览里**必须带协议说明**。Anthropic 的请求体里 `messages` 只剩一条 user，

## 第十二段 · Code（Agent）页：模型自己调工具改卡

用户原话：
> 请为角色卡编辑新增【code】要求支持Agent 工具，能够使用skill，常规比例下，
> 按照左侧侧是角色卡json，右侧是Agent会话，上方有折叠菜单有【当前skill列表】，

> 在手机（以及竖立显示器）单独显示【code】或【Agent 】可以通过切换来显示来一个页面，
> 【code】不受之前的【第一段】影响，不添加【第一段】

第 14 个选项卡。前面那些 AI 功能都是「生成一段文本、你自己贴进去」，这一页是
**模型自己调工具改卡** —— 所以多了三样以前没有的东西：工具协议、Agent 循环、会话历史。

### 版式：一套 HTML，两种排布

| | 常规比例 | 手机 / 竖屏 |
|---|---|---|
| 左栏 | 角色卡 JSON（只读 + 高亮） | 按顶部 `【code】/【Agent】` 二选一 |
| 右栏 | Agent 会话 | 同上 |

判定用 `@media (max-width: 820px), (orientation: portrait)`。⚠ **不能用 `display:none` 藏另一栏** ——
那样切回来时滚动位置和输入框内容都还在 DOM 里但看不到，用户会以为丢了。做法是两栏都渲染、
只切 `view` 类，切换状态存 `stCodeUi.view`。

`#st-panes` 在 Code 页要加 `st-code-mode`（`overflow:hidden; padding:0`）——
否则外层那个滚动容器会把两栏各自的高度撑坏，右栏的消息列表滚不动。

### 工具协议：10 个工具，两套壳

`read_card` / `write_text` / `write_list` / `list_world_entries` / `read_world_entry` /
`add_world_entry` / `update_world_entry` / `delete_world_entry` / `list_skills` / `read_skill`

| | OpenAI 兼容 | Anthropic |
|---|---|---|
| 声明 | `tools[].function.{name,description,parameters}` | `tools[].{name,description,input_schema}` |
| 发起 | `choices[0].message.tool_calls[]` | `content[]` 里 `type:'tool_use'` |
| 回传 | `{role:'tool', tool_call_id, content}` | `{role:'user', content:[{type:'tool_result',...}]}` |

**写路径一律白名单**（`ST_CODE_TEXT_PATHS` / `ST_CODE_LIST_PATHS`）。放模型自由写路径
等于给它一次「把 `card` 整个写成字符串」的机会 —— `stSet` 只写标量叶子，写坏了整块都没了。
越权路径**报错而不是静默**（静默的话模型会以为改成功了，接着往下做）。

**删世界书条目进回收站**（`stCode.trash`），能撤回。删是不可逆操作，不给后悔药的 AI 很危险。

**`list_world_entries` 只给摘要**（编号 / id / 备注 / 关键词 / 启用 / 正文开头），
要正文得单独 `read_world_entry` —— 世界书几十条，一次全塞进上下文直接把窗口烧掉。

### Agent 循环

### 1. `static_check.js` 的标签配平一直在误报

## 第十六段 · Code 页：让 agent 能读改「正则 / 酒馆助手 / MVU / 状态栏」

用户原话：**「请问可以让agent能够读取改写正则，酒馆助手和mvu状态栏吗？」**
→ 我查了一圈（白名单拦着写、状态栏/MVU 根本不在卡字段上），给了个方案 → **「按你说的做吧」**。

### 16. 先搞清楚的：这不是四样平行的东西

调研的**唯一**有价值的产出是这张表 —— 它决定了后面所有设计：

| 用户说的 | 实际住在哪 |
|---|---|
| 状态栏 | 「状态栏界面」那条**正则**的 `replaceString` |
| MVU 变量结构 | 写着 `registerMvuSchema` 的那条**酒馆助手脚本**的 `content` |
| 正则 | `card.regex[]` |
| 酒馆助手 | `card.thScripts[]` |

**只有两个真容器。** 而且 `card.statusBar` / `card.mvu` 只是编辑器的**工作副本** ——
对别人的卡来说读它们是读了个**假象**。

### 17. 两套形状，各有各的理由

- **状态栏 / MVU 是「一份」** → 整份替换（`read_doc` / `write_doc`）。关键洞察：
  **往返通道早就有了** —— 状态栏是 HTML（`stSbDocHtml` ↔ `stSbParseDoc`），
  MVU 是 Zod（`stMvuZodCode` ↔ `stMvuParseZod`）。所以不用造新格式，
  直接把「模型最擅长的文本」给它就行，**别给它那棵树**。
- **正则 / 脚本是「一列」** → 按条目（`read_regex` / `write_regex` / `read_th` / `write_th`），
  抄世界书那套。理由：**整列替换会静默丢东西**。

### 18. ⚠ 核心风险：抹掉状态栏和 MVU，而且模型不会知道

**状态栏就住在那条正则里，MVU 的 Zod 就住在那个脚本里。**
模型把它们当普通条目删改 = 整个抹掉，**没有任何报错，卡看起来还是好的**。

`stCodeEntryGuard` 是闸：认出 sbShow / hide / wait / done / sbHide、认出
`MagVarUpdate` / `registerMvuSchema` 就拦住并指路。**只改开关是唯一例外。**

⚠ **`stCodeOnlyToggle` 的 bug（坑 48）**：只看「参数里有没有多余字段」，
于是 `{mode:'delete', id:'状态栏界面'}` **恰好也在白名单里** → 删状态栏被放行。
**必须同时看意图（`mode==='update'`）和参数。** 套件 E6 当场抓到。

### 19. 顺手修的三个真问题

1. **`stMvuParseZod` 只认 ASCII 标识符（坑 51）** → 中文卡 `const 角色 = z.object({…})`
   **整个读不回来**，用户只会觉得「我这张卡明明是好的」。抽 `ST_MVU_IDENT` 两处共用。
   *是写测试时随手用了中文标识符才撞出来的* —— 又一次证明**测试用什么数据很重要**。
2. **`read_card` 说假话（坑 49）** → 问 `regex` 回「卡里没有这个字段」，
   模型就会得出「这张卡没有正则」然后压根不去动。**报错信息说错话比不报错更坏：
   它会让人放弃。** 而且我把指路写在「字段不存在」分支里 —— `regex` 是真实字段，
   那个分支**永远走不到**，等于没写。
3. **大值硬截断** → 模型拿到一段**看起来完整**的 JSON，当成全部，基于半截数据做决定。
   加 `stCodeBrief`：数组给「N 项 / M 字」+ 前 12 项一行摘要，对象给键清单。

### 20. 回收站要带 `kind`

`stCode.trash` 从「裸条目」变成 `{kind, item}`（`book` / `regex` / `th`）——
否则撤回一条正则会被塞进世界书。`stCodeUndoDelete` 按 `kind` 分流，兼容早期草稿。
