### 五个设计决定（都有代价）

1. **存 `aiChatSessions`，不塞 `aiChatConfig`。** 后者是「设置」，被 `st-ai.js` /
   `apig-verify.js` 断言着，且每次「保存设置」整份重写 —— 聊天记录塞进去等于每点一次
   保存就重写几百条消息。
2. **人设快照按内容去重**（`personas` 表 + `pid` 引用，key = FNV-1a + 长度）。
   同一张卡聊 20 段只存一份世界书。快照**一旦生成不再改写** ⇒ 「当时用的哪份人设」永远准。
3. **`firstSeg` 不进快照。** 它在 `API_GLOBAL_FIELDS` 里属于「钥匙」那组，
   `syncAiCfgSourceUI()` 每次都会盖回去 ⇒ 存了只会得到「切过来对、动一下变回去」的假状态。
4. **`tavernTimed` 按会话单独存，不进快照。** 它每条消息都在变，进快照等于每发一句多一份副本。
5. **页面刚打开只恢复消息、不恢复人设。** 打开时 `aiConfig` 才是「现在生效的那份」；
   反过来的话用户导入新卡、刷新一下就被旧快照盖掉。**只有主动切换**才拿快照覆盖。

顺带把 `334` 里两处写死的 `40` 收成 `AI_CHAT_HIST_MAX`（会话恢复也要用它）。

### 踩到的三个坑

**① `</style>` 闭标签原先住在最后一个 CSS 模块（`028`）的末尾。**
新加的 `029` 于是整段拼到样式块**外面**：页面不报错、控制台不报错、`check.js` 6 项全绿、
`BUILD-SYNC` 也绿（产物确实跟 `src/` 一致），但 `.ai-hist-panel { display: none }`
**根本没生效**，面板一直是 `block`。唯一判据 = `getComputedStyle` 读 `display`。
修法：把 `</style>` 挪到 `100-BODY` 的**第一行**（拼装结果逐字节不变），
以后 CSS 直接往 `style/` 组末尾追加。同一句话写进了 `manifest.json` 的 `note`。

**② 会话标题永远叫「新对话」。**
空会话一建出来 `aiSessSaveCurrent()` 就写标题，那时还没用户消息 ⇒ 写成占位符 `'新对话'`；
之后 `if (!cur.title)` 判断它**已经非空**，再也不更新。判据是探针 B5。
修法：占位符不算标题，拿到真标题前一直重算。

**③ 自己引出来的回归：点「应用」补出第二句开场白。**
`applyAiSettings()` 原来写 `if (!chatHistory.length) appendAiGreeting()`。以前页面加载时
聊天框是**空的**，所以「chatHistory 空」等价于「屏幕上没有气泡」；会话恢复之后
chatHistory 空、但开场白气泡**已经在屏幕上** ⇒ 再补一条。改成 `refreshGreetingIfFresh()`
（它还会看有没有用户气泡 / 失败气泡），判据收归一处。探针 A7 / A8 盯着，
A8 是「点之前确实有开场白」的对照组 —— 少了它 A7 就是空对空。

⚠ **E 组第一版是空对空的**，值得单独记：`#ai-card` 默认带 `ai-collapsed`，
`.ai-collapse-wrapper` 是 `grid-template-rows: 0fr` ⇒ 高度 0。在 0×0 的盒子里比

否则截出来是白板（第一次截 420×900 就白了一张）。

## 第三十四段（同日）· 每个 AI 调用点显示 token 用量（发送 / 应答分开）

用户原话：「请添加每次调用ai功能时，在相应板块的适当位置添加tokens调用数(发送与应答分开)」

### 做成什么样

全站 **9 个真的会发请求的地方**，每处都在自己那块界面里报数：

| 板块 | 位置 |
|---|---|
| 【ai对话】 | 回复气泡**下面**独立一行 `发送 1 234 / 应答 567 tokens` |
| 编写器 · 预制块 / 人设生成器 / 世界书扩写 / 单条改写 / 开场白 / 测试连接 | 各自的 `✅` 状态行末尾（` · 发送 … / 应答 … tokens`） |
| API 全局配置 · 测试连接 | 弹窗状态行（按钮上本来就写着「会消耗几个 token」，现在把几个说清楚） |
| Code 页 Agent | 每轮 `🤖 Agent` 角色行后面一个小徽标（**每轮各记一份**） |

### 结构上的决定

- 取用量全收在 `264` 一处：`stAiUsageOf` / `stAiUsageMerge` / `stAiUsageNote` /
  `stAiUsageEstimate` / `stAiUsageText` / `stAiUsageSuffix` / `stAiUsageWith` /
  `stAiUsageSnapshot`。各板块只负责「把哪个函数塞到自己的 UI 里」。
- **`stAiPostChat` 收成唯一出口**（原先 `stAiChat` / `streamChat` / `nonStreamChat` /
  API 测试连接各有一份 `fetch`）⇒ 「400 就丢掉 `stream_options` 重发一次」这条兜底
  只写一遍。API 测试连接是这一轮顺手并进去的第 5 份实现。
- `stAiUsageMerge` **逐字段取 max**，不能覆盖：Anthropic 流式把用量拆成
  `message_start`（只有 input）与 `message_delta`（只有 output）两条事件。
- 拿不到用量 ⇒ `estimateTokens` 估算 + **界面上带 `≈`**（六之二十七：回落必须说出来）。
- 会话存的是 `stAiUsageSnapshot()` 的**结构化副本**，不是显示文本 —— 存文本的话
  以后改格式，旧会话里还是旧格式。

### 踩到的坑

1. **`.ai-usage` 靠 `flex-wrap` 才能独占一行。** `.ai-msg` 是 `display:flex`，
   直接 append 会被排成气泡右边的**第三列**；而气泡 `max-width:78%` + 按钮 24px
   本来就放得下 ⇒ 看起来像「样式没生效」。解法：`.ai-msg` 加 `flex-wrap:wrap`，
   标签 `flex-basis:100%` + `order:9`。
2. **不能塞进气泡里**：气泡内容每帧 `textContent` 整体替换，子节点会被抹掉。
3. **切会话会丢标签**：`aiSessCollectBubbles` 不加 `usage` 的话，切走再切回来就没了。
