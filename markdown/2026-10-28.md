## 人设生成器加上「参考素材」：勾世界书条目 / 额外导入世界书

用户原话：

> 请为 角色生成器 添加 能够选择当前世界书某一条目(某些条目)来进行角色生成，
> 或者额外导入世界书来生成角色

「角色生成器」= 编写器的 `persona` 选项卡（人设生成器，`stPanePersona`）。
两路来源**都做了**，而且可以同时用（用户说「或者」，但同时开着没有任何坏处，是超集）。

### 改了什么

面板上在「把角色卡名字当人物姓名」和「模板」之间多了一个**折叠块**「参考素材（世界书）」：

- **本卡世界书**（`card.bookEntries`）多选；
- **额外导入的世界书**（「📖 导入世界书 JSON」）—— `parseWorldBook()` 解析后存进
  `stEditor.personaLore`，**只喂这一次生成、一个字都不进卡**。

两路**同构**（卡内条目和 `parseWorldBook` 的产物同一个形状），所以一套渲染通吃。
勾中的条目由 `stPersonaLoreBlock()` 折成一段，插进 `stPersonaUserPrompt()` 的
「要求」和「模板」之间 —— 它跟要求一样是**输入**，模板是**输出的形状**。

产品：1 708 556 → **1 729 585** 字节（32 833 → 33 170 行），
sha1 `c5ee38fe…` → **`b940ebc16642b45746dfd8c17e512d02e7b6754b`**。

### 四个「差一点就写错」的地方

1. **导入绝不能写进 `card.bookEntries`。** 「额外导入」的全部意义是「手上有一份书，
   但不想把它塞进这张卡」。顺手 `push` 进去就是**偷偷改卡**。
   `_reverse24.js` 的 R2 专门钉这条（只让一个断言红，因为这个承诺本来就只有一个断言盯着）。
2. **勾选键必须带来源前缀**（`'card:<id>'` / `'imp:<id>'`）。两边 `id` 各自独立生成
   （导入的是 `'e0' 'e1'…`），裸 id 会把两本书里的两条混成一条。也不带下标 —— 会被增删挪走。
3. **「已选 N 条」里的 N 必须是「能喂进去的」N。** 条目被删之后 `personaPick` 里
   **还留着那个键**（清理是懒的）⇒ 报 `length` 会显示「已选 3 条」而模型只收到 1 条。
   `_reverse24.js` 的 R3 打的就是这个差。
4. **少喂几条必须说出来**（`missing` / `dropped` / `truncated` 三个数，生成完点名原因）。
   ⚠ 界面上勾着 5 条、模型只看到 3 条，而生成结果看起来**完全正常** —— 本功能最容易出的坑。

### 三条**假红**：不是产品坏了，是断言挑错了元素

### 线上复核：**拿到了两条决定性判据，但整文件 sha1 没拿到**（网络严重限速，不是阻断）

本机到 GitHub Pages 边缘节点（`185.199.108~111.153`）**被限到 ≈413 B/s**，
`api.github.com` 正常（3.4 s / 200，对照组）。**强制 `-4` 也一样** ⇒ 不是 IPv6 优先。

| 判据 | 结果 |
|---|---|
| `Content-Range` 里的线上总字节 | **1 729 585** = 本地 1 729 585 ✅（**旧版是 1 708 556**） |
| Range `103175-103975`（801 B，**横跨新增的 `.st-lore-list` CSS 块**） | **逐字节一致** ✅ |
| Range `1273000-1273400`（JS 区，401 B） | ❌ 超时（60 s / 90 s 都 0 字节） |
| 整文件 sha1 | ❌ 没拿到（1.7 MB ÷ 413 B/s ≈ 70 分钟） |

⇒ **结论：线上确实是这一版**（旧版在那个偏移上根本没有 `st-lore-list`，
801 字节全等 + 总长恰好等于本地，两件事同时成立不是巧合）。
⚠ 但**整文件 sha1 这一条最强的判据仍然缺着**。下一轮网络好时补一次
`sha1sum` 全量比对（期望 `b940ebc16642b45746dfd8c17e512d02e7b6754b`），别因为这次「够用了」就跳过。

⚠⚠ 方法论：**「取不到」和「内容不对」必须分开记** —— 一开始全超时，很容易写成「复核失败」，
但那句话会被下一轮读成「部署可能有问题」。实际是**网络只给 413 B/s**，
换成「总长 + 小载荷 Range」两条判据就能下结论。**判据要挑「小到能跑完」的**，
不是挑「看起来最权威」的那个。
