## 日历的「今日」按钮改成**显示当前日**（保留点它回到今天）

**用户原话**：「修改主页的日历部分，将【今日】改为显示当前日（比如今天是1日就显示1日），
并保留原有的回到当前日的功能」

**产品文件**：`saki.html` 1 700 226 → **1 702 668** 字节（32 709 → 32 739 行），
sha1 `f86775e03e8d…` → **`717837424a9eddf717564d08811520fdc5d6661f`**。

### 一、改了什么

日历头部那三个标签里，`renderCalendar()` 原来只写年份和月份，那个按钮的文案是**写死在 HTML 里**的。
新增 `updateTodayBtn()` 把它写成 `<本地日>日`（`2日` / `31日`）：

```js
function updateTodayBtn() {
    const el = document.getElementById('today-btn');
    if (!el) return;
    const d = String(new Date().getDate());
    if (el.dataset.day === d) return;      // 跨日才写 DOM
    el.dataset.day = d;
    el.textContent = d + '日';
}
```

- 按钮加了 `id="today-btn"`；HTML 里那个「今日」**留作脚本跑起来之前的兜底**（旁边加了注释说明）。
- **`resetToToday()` 一个字没改** —— 用户明确要求「保留」的那一半。
- 两个调用点：`renderCalendar()`（初始化 + 每次翻页 / 切视图）+ `updateClock()`（每秒的 tick，管**跨 00:00**）。

### 二、两个「差一点就写错」的地方

**① 日期必须取本地，不能跟着时区选择器走。**
`updateClock()` 用的是 `getClockTimeParts()`，那个**跟着时区选择器**（时钟能切成东京 / 纽约时间）；
而日历的「今天」永远是**本地**的今天（`resetToToday()` 就是 `new Date()`）。
顺手「复用时钟那一套」的症状是**「按钮写着 3 日、点下去跳到 2 日」**这种自相矛盾。

**② ⚠ 跨日缓存不能挂在模块级 `let` 上。**
第一版写的是 `let todayBtnDay = -1;`。**收尾 grep 调用点时才发现的**：
`updateClock()` 除了初始化那一处，**在 `setClockTimezone()` 里还有一处调用点**，
而那个 `let` 声明在它**之后** —— 现在不会执行到（要点击才触发），
但**哪天有人把它挪到脚本求值期就会撞 TDZ**（`ReferenceError`，症状离现场很远）。
改成把缓存挂在**元素自己的 `data-day`** 上，顺序依赖整个消失。
⇒ 教训：**「函数写好了」不等于「调用点的顺序也是安全的」**，声明与调用的相对位置要专门看一眼。

### 三、断言：改之前这个按钮**一条断言都没有**

`grep '今日\|today-btn\|resetToToday' _verify/*.js` **全空** —— 也就是说这个按钮的文案
在此之前等于**没有任何断言看着**（正是记忆里那条「UI 的承诺没有断言看着 = 你在静默违约」）。
`smoke.js` 新增 5 条（91 → **96**）：

| 断言 | 盯什么 |
|---|---|
| 按钮上显示的是当前日（`N日`） | 用户要的那一半 |
| 前提：日历处于「日」视图 | ⚠ **前提本身要摆出来**：视图切到「月 / 年」时 ＜ 退的是年，下面那条对照会**假红** |
| 对照组：点 ＜ 之后确实离开了当前月 | ⚠ **对照组**：不先离开当前月，「点完回到本月」**永远为真** |
| 对照组：翻月之后按钮上的日子没变 | 「不该发生」的另一半：文案**不跟着浏览的月份走** |
| 点「今日」回到当前月 | 用户要保留的那一半 |

⚠ 判据**全部现算**（`new Date().getDate()`），**一个日期都没写死** —— 写死的话明天就假红。
⚠ 两处点击都**判空后再点**（元素不在时 `null.click()` 会抛异常 ⇒ 整个套件中断、
后面的断言一条都不跑、汇总行也不打 —— 「红」会悄悄变成「静默少走」）。

### ⚠⚠ 写这份 harness 时撞上的静默陷阱

`_reverse21.js` 解析汇总行用的是 `(\d+) 通过 / (\d+) 失败`，
而 **`smoke.js` 打的是英文的 `96 passed, 0 failed`** —— **照抄那条正则一条都匹配不上**，
而症状是「基线跑完了 ✅」（其实 `summaryOf` 返回 `null`，被读成了「有汇总行」）。

失败行的形状也不同：smoke 是 `❌ <名字>  actual=<json>  expect=<…>`，
而 **`expect` 传函数时会把函数源码整段打出来** ⇒ **不能按行尾切**，只能从 `  actual=` 处截断。

⇒ **同族**：`run-all.js` 文件头那条「手写 `for` + `grep`/`tail` 会让格式不匹配的那几套**静默变空行**」
（六之五十二 / 六之五十一）。**跨套件复用解析逻辑前，先看那个套件到底打什么格式。**

⚠ 另外：断言名里带**动态值**（今天几号 / 这个月是几月）⇒ 反向测试的 red / green 名单**必须现算**，
写死就会在别的日子失效（而且表现是「存在性闸门」报红，不是静默 —— 这一点还好）。

### 七、发布（两个分支 + 线上字节）

本机**不能切分支**（六之八十二：`git checkout main` 要删掉整棵 `android/`，`G:` 上删除 ≈17 s/文件，
8 分 22 秒才删掉 24/45 就被杀）。所以两条路都不碰工作树：

1. **`apk`**：HEAD 本来就在 `apk` 上，直接 `node _verify/api-push.js --go --branch=apk`
   ⇒ 远端 = 本地 = `a532c97df0c3f39f6b5a8ea7a65e5f8c4aca9d61`，**同 sha、零分叉**。
2. **`main`**：用 `git symbolic-ref HEAD refs/heads/main` 把 HEAD 挪过去（**不碰索引 / 工作树**），
   再 `api-push.js --go --branch=main` ⇒ 远端 = 本地 = `16276384dd0aa2ef461478f458c19f690e6cae41`，
   推完把 HEAD `symbolic-ref` 回 `refs/heads/apk`。
   - `api-push.js` 全程只走 `rev-parse HEAD` + 对象库（`rev-parse <sha>^{tree}` / `:<path>`、
     `log`、`ls-tree`、`rev-list`、`diff-tree`），**不需要索引**，所以这条路成立。
   - ⚠⚠ **`--branch=X` 只指定远端 ref 的名字，内容永远取自 HEAD**（六之八十）⇒
     推 `main` 之前**必须先确认 `git rev-parse --abbrev-ref HEAD` 是 `main`**。
     上次 `--branch=main` 而 HEAD 还在 `apk`，**只是靠 `force:false` 被 GitHub 拒掉才没出事**。
   - `main` 那个 commit 是**纯 plumbing** 造的：`GIT_INDEX_FILE=<tmp> git read-tree main` →
     `update-index --force-remove <android/*>` / `--add --cacheinfo 100644,<sha>,<path>` →
     `write-tree` → `commit-tree <tree> -p main` → `update-ref refs/heads/main`，最后 `rm -f` 临时索引。
     ⚠ **`--cacheinfo` 对全新路径要 `--add`**，否则 `fatal: cannot add to the index - missing --add option?`
     （这次两个新路径 `_verify/_reverse22.js`、`markdown/2026-10-02.md` 就撞上了；闸门「非 android 差异: 2」抓住）。
   - 分叉核对：`main`（`1627638`）与 `apk`（`a532c97`）都是 `cc23dcfb` 的**兄弟**，
     互不为祖先 ⇒ 拿 `apk` 当 HEAD 去 dry-run `main` 会报「不是快进」，**这是对的，不是故障**；
     而它是只读的（"远端 ref 未改动"），正好当**问服务器**的手段（六之七十八）。
3. **跟踪 ref 要手改**：`api-push` 之后 `refs/remotes/origin/*` 是**过期**的（六之七十八）⇒
   `git update-ref refs/remotes/origin/main 1627638…` / `origin/apk a532c97…`，**回读**确认，
   然后 `git status -sb` 只剩 `## apk`、**没有幻影 `ahead N`**。
4. **线上字节**（唯一判据，六之六十四）：`node _verify/deploy-check.js`
   ⇒ 线上 `https://yansaki.top/index.html` **200 / 1 702 668 字节 / sha1 `717837424a9eddf717564d08811520fdc5d6661f`**，
   与本地 `index.html` **逐字节一致**（`saki.html` 同 sha ⇒ 发布副本同步过）。
   再直接 `https.get` 线上页面 grep 四个锚点（`id="today-btn"` / `onclick="resetToToday()"` /
   `function updateTodayBtn()` / `function resetToToday()`）**全部命中**，不靠传递性。
   - ⚠ 顺手撞到一次「写死的数字」：我脚本里把 `updateTodayBtn()` 的出现次数写成「定义 1 + 调用 2 = 3」，
     实测 **5**。真实构成 = **2 处注释**（HTML 注释 + JS 注释）+ 1 定义 + 2 调用（六之七十）。
   - `resetToToday()` **逐字节未动**：`git diff cc23dcf a532c97 -- saki.html` 里
     `function resetToToday() {` 及其函数体全是**上下文行**（前导空格，非 `+`/`-`）。

## 世界时间加上**日期偏移徽标**（`【D+1】` / `【D-1】`）

**用户原话**：「在世界时间中，如果日期晚一天或者早一天则用小字显示【D+1】或者【D-1】」

**产品文件**：`saki.html` 1 702 668 → **1 708 556** 字节（32 739 → 32 833 行），
sha1 `717837424a9eddf717564d08811520fdc5d6661f` → **`c5ee38fea71ab4d78a648b15262f9db10c3383cb`**。

### 一、先问了一句

「世界时间」在代码里**没有对应的名字**（`grep 世界时间` 零命中），指的是时钟卡片那个 23 城时区选择器。
而标记放哪儿是个**纯视觉取舍**，猜错就是白跑一轮发布 ⇒ 用 `AskUserQuestion` 问了三选一：

1. **时钟旁边一个小徽标**（用户选的）
2. 时区格子上各标各的
3. 两处都标

### 二、改了什么

`#clock` 右边新增 `<span id="clock-day-offset">`，三个新函数：
`getClockDateParts()`（所选时区当天的年月日）/ `getClockDayOffset()`（整数天差）/
`updateClockDayOffset()`（写 `【D±N】`，偏移 0 写空串）。
调用点加在 `updateClock()` 里（紧跟时钟文案那次写入）⇒ 每秒刷新、跨 00:00 自己翻；
`setClockTimezone()` 本来就会调 `updateClock()` ⇒ 换城市时跟着换。

CSS：`.clock-day-offset` + **`.clock-day-offset:empty { display: none }`** +
一条 `body.retro-mode .clock-day-offset`。

### 三、三个差一点写错的地方

1. **整数天差必须靠 `Date.UTC(...)` 折算。** 两个日历日期各折成「当天 00:00 的 **UTC** 毫秒」
   再相减，结果必然是整数天；直接拿两个 `Date` 相减会踩夏令时（切换日 23 / 25 小时，
   除不尽 `86400000`，`Math.round` 会在「只差 1 小时」时算成 1 天）。
2. **偏移 0 必须写空串 + CSS `:empty` 收起。** 只清 `textContent` 不够：元素还在，
   一个 `margin-left` 会把时钟往左推 —— 而「本地时间」下它**永远是空的**，是**常态**不是边角情况。
3. **徽标跟日历「今日」按钮判据不同源，别合并。** 徽标取**所选时区**日期、按钮取**本地**日期。
   混起来就是「时钟说东京是 3 日、日历的今日按钮也变成 3 日」。

### 四、断言（`smoke.js` 96 → **104**，8 条）

| 断言 | 作用 |
|---|---|
| 前提：时钟卡片里有那个日期徽标元素 | 元素不在时后面全崩 ⇒ 先摆前提 |
| 前提：城市表里至少有一个时区此刻跨了天 | **覆盖率闸门**，否则下一条根本没被测到（而它会绿） |
| 对照组：本地时间下徽标为空 | 基准不标自己 |
| 跨天的时区：徽标与独立算法一致（含方向） | 主断言（**文案**） |
| 跨天的时区：徽标在时钟右边 | 主断言（**位置**，rect 比较） |
| 对照组：切回本地时间后徽标又变空 | 证明上一条不是「反正一直有字」 |
| 前提：时区网格里有格子 | 否则最后一条对空网格**天生为真** |
| 时区格子上没有多余的 D+ / D- 标记 | 需求只说了「时钟旁边」 |

⚠⚠ **位置那条是后补的，而且必须补**：用户原话是「时钟**旁边**」——
只断言 `textContent` 的话，一个把徽标 `position:absolute` 到卡片角落的实现照样全绿。
判据是 **rect 比较**（`badge.left - clock.right >= 0` 且 `badge.width > 0`），
**不是拿 CSS 算**（CSS 算不出元素在视口里的 x，六之六十二）。
实测：`display=true 与时钟的间距=9px 宽=52px`；同时实测**本地时间下**徽标
`display=none`、宽 0，且 `clockRight == rowRight == 563` ⇒ **时钟没被挤走**。
⚠ 实拍截图 `_verify/shots/clock-day-offset.png` 也确认了外观（大数字右边一个小字 `【D-1】`）。

⚠⚠ **期望值走一条跟产品不同的机制**：`timeZoneName:'longOffset'` 取偏移分钟数 → 加时间 →
读 UTC 年月日，而不是产品那条 `formatToParts(year/month/day)`（六之二十六）。
⚠⚠ **探针城市现扫、不写死**：同一个城市上午看是同一天、晚上看就是下一天。
实测跨了 00:00 之后它**自己换了探针**：23:22 取 `Asia/Tokyo`（`【D+1】`、4 个城市跨天）→
00:1x 取 `Asia/Bangkok`（`【D-1】`、14 个城市跨天），日历那个「今日」按钮也跟着变成 `3日`。
⚠ **断言名一律不带动态值** ⇒ 反向测试的存在性闸门不会随时辰假红（新规则六之八十四）。
