### ⚠⚠ 本轮最值钱的一个坑：「仓库 API 说你有权限」≠「token 有权限」

新 token 换上去之后，看着一切都对：

- `GET /user` → 200，登录名 `MuyueJusan` ✓
- `GET /repos/MuyueJusan/YanSaki` → 200，**`permissions.push = true`** ✓
- 读 ref / 读 Actions runs / 读 contents → 全 200 ✓
- 但 **`POST /git/blobs` → 403**：`Resource not accessible by personal access token`

**`permissions` 那个字段说的是「你这个*用户*对这个仓库的角色权限」，不是
「这个 *token* 被授予了什么」。** 仓库是你自己的 ⇒ 它照样报 `push: true`，
而 token 可能只被授予了只读。⇒ **唯一可信的判据是真的写一次。**

⚠ 而且要用**非破坏性**的写：`POST /git/blobs` 造一个**游离 blob** ——
不挂任何 ref、不改分支、GitHub 自己回收。这是「确认能推」的最小代价探针。
（比「随便推个提交试试」好得多，那个会污染历史。）

### 缺的是哪个权限：让 GitHub 自己说

403 的响应头里有：

```
x-accepted-github-permissions: contents=write
```

⇒ 精确答案：**Repository permissions → Contents → Read and write**。
比猜「大概是 Contents 吧」强得多 —— **失败信息里本来就有答案，别自己推。**

## APK 封装版（用户要「fork 一份，在里面做 APK」）

### fork 做不了 —— 而且失败信号是**假的**

GitHub **不允许 fork 自己拥有的库**。实测 `POST /repos/MuyueJusan/YanSaki/forks`
返回 **202 Accepted**，看着像成功，但核实下来：

- 返回体里的 `id = 758001742` 就是**源库自己的 id**
- `forks_count` 仍是 **0**，`/forks` 列表 0 个，库总数还是 11

⇒ **202 是静默空操作，什么都没建。** 以后判「建成了没有」只能去**列出来看**，
不能看状态码。

用户最终选了**同库加 `apk` 分支**（站点只从 `main` 部署，所以完全隔离）。

### 两个大坑

**① 页面必须跑在真实 origin 上，不能用 `file://`。**
产品里 `localStorage` 用了 **76 处**。`file://` 是 opaque origin ⇒ 一访问就抛
`SecurityError`，表现是「设置全部存不住」且**界面不报错**。
解法：保留域名 `appassets.androidplatform.net` + `shouldInterceptRequest` 读 assets
（学 androidx 的 WebViewAssetLoader，但零依赖、纯 framework API）。

**② javac 必须用 JDK 11/17，不能用 21+。**

| javac 来自 | d8（R8 8.2.2 / build-tools 34） |
|---|---|
| JDK 11 | ✅ |
| JDK 21 | ❌ 内部 NPE |
| JDK 24 | ❌ 内部 NPE |

JDK 21/24 在 `-target 8` 下，对**带 `this$0` 的内部类**写出的 class 文件 d8 解析不了：
`NullPointerException: Cannot invoke "String.length()" because "<parameter1>" is null`。
两边 class 主版本号**都是 52**，`-g:none` 也去不掉 ⇒ **看字节看不出来**。
而且 `-bootclasspath android.jar` **只允许配 `-target 8`**（11+ 报「不允许选项
--boot-class-path」）⇒ 「改成 target 11 绕开」这条路是堵死的。
最小复现：`android/tools/repro-d8-javac/`。

### ⚠⚠ 本轮最该记住的：**我拿一个假绿得出了错误结论**

第一轮对照实验里 `-target 11` / `-target 17` 显示 d8 通过，我差点据此改方案。
实际是 **javac 编译失败 → 0 个 class → jar 是空的 → d8 对空输入「成功」**。
我的实验脚本把 javac 的 stderr 重定向丢了，所以什么都没看见。
⇒ 后来每一条都先 `find -name '*.class' | wc -l`，为 0 就判「本条结论无效」。
`build.sh` 里也补了这条守卫（`NCLASS >= 3`）。

### ⚠ 另外两个「看着像失败其实不是」

- **`apksigner verify --verbose` 报 v1/v2 `false`** —— 它只校验**该 APK 的 minSdk
  所需**的方案。minSdk 29 只需 v3，所以 v1/v2 一律打 false，**那不是「没签」是「没查」**。
  显式给 `--min-sdk-version 23` 后：v1 + v2 + v3 **全 true**。
- **zipalign 把 "successful" 印成 "succesful"**（少一个 s），我 grep 人话字符串
  就把一次成功报成了失败。改成**看退出码**。
