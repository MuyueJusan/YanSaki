### ⚠⚠ 本轮最值钱的一个坑：「仓库 API 说你有权限」≠「token 有权限」

新 token 换上去之后，看着一切都对：

- `GET /user` → 200，登录名 `MuyueJusan` ✓
- `GET /repos/MuyueJusan/YanSaki` → 200，**`permissions.push = true`** ✓
- 读 ref / 读 Actions runs / 读 contents → 全 200 ✓
- 但 **`POST /git/blobs` → 403**：`Resource not accessible by personal access token`

**`permissions` 那个字段说的是「你这个*用户*对这个仓库的角色权限」，不是
「这个 *token* 被授予了什么」。** 仓库是你自己的 ⇒ 它照样报 `push: true`，
而 token 可能只被授予了只读。⇒ **唯一可信的判据是真的写一次。**

⚠ 而且要用**非破坏性**的写：`POST /git/blobs` 造一个**游离 blob** ——
不挂任何 ref、不改分支、GitHub 自己回收。这是「确认能推」的最小代价探针。
（比「随便推个提交试试」好得多，那个会污染历史。）

### 缺的是哪个权限：让 GitHub 自己说

403 的响应头里有：

```
x-accepted-github-permissions: contents=write
```

⇒ 精确答案：**Repository permissions → Contents → Read and write**。
比猜「大概是 Contents 吧」强得多 —— **失败信息里本来就有答案，别自己推。**
