## ⑧ 验证习惯（展开版 = `RULES.md` 六；通用手法在技能 `verify-single-file-html-app`）

- ⚠ **「发生了」必须配「不该发生」的对照组**，否则可能**永远为真**。⚠ **断言方向本身就是需求** —— 改主意**先改断言、看它红，再改产品**。⚠ **数组不能用 `===` 比**；⚠ `check(name, actual, pred, expect)` **只收 4 个参数**。⚠ **折叠面板的「看不见」量 rect 量不出**（裁切不改 `rect`）⇒ 量外层网格 + 命中测试。
- ⚠⚠ **「跑完了」≠「每条都跑到了」**（提前 `process.exit()` 静默吃掉后面）；⚠ **「从来没发生过」要拿当时的快照支撑**，不能靠回忆 ⇒ **锚点一律选结构性的**。
- ⚠⚠ **写死清单 / 写死数字每次加东西都会来收账** ⇒ **改推导式 / 跟基线比**。⚠⚠ **顺序型断言有三种静默形态**（六之十七）—— **都不会当场红**，必须人工核。⚠ **探针造的文件无条件删**；⚠ **改了断言名要重跑对着它的反向测试**。
- ⚠⚠ **新增功能可能让旧套件的「前提」失效，而不是打坏产品** —— 断言**集体假红**时**看数值是不是全 0**（全 0 = 元素不可见，不是不达标）⇒ **让断言走真实路径**。⚠ **靠 class 变 `position:fixed` 的卡片隐藏必须写 `:not(.全屏类)`**，且**要断言 computed `display`**。
- ⚠ **`saki.html` 是 CRLF** ⇒ JS 里 `.` **不匹配 `\r`**，`/\/\/.*$/` 这类正则**整条静默失败**。**凡 `$` 锚行尾的正则先问「这文件是 CRLF 吗」。** ⚠ Git Bash `grep -c $'\r'` 对 CRLF 报 0（**不可靠**）—— 要数就 Node 读 `latin1` 后 `match(/\r\n/g)`。⚠ `markdown/` 是**纯 LF**。

**`check.js`（`G:\saki\_verify\`）** —— 改完先跑（自己抽页面、自己解析，**不用先 `extract.js`**）；5 项 `SYNTAX` / `MISSING` / `DUPLICATE literal ids` / `UNDECLARED` / `ESCAPE-GATE`。⚠ **它读页面不读生成物** —— **过时的输入比没有检查更坏**。⚠ **转义闸门**判据 = 抹白安全包装后剩下的 `+ 变量` **多重集**跟 `ESCAPE_ALLOW` 逐字一致（**新加构建函数必须来改白名单**）。

**跑套件** —— ⚠ **整跑一律用 `run-all.js`**（手写 `for` + `grep`/`tail` 会让格式不匹配的那几套**静默变空行**）；runner 把「收尾行解析不出 / 有未分类 `.js` / 有失败项」当**硬错误**。⚠⚠ **它抓不到「某套只跑了一部分」** —— 实测**并行跑两套 harness** 时外部层只跑 1/371 照样打「✅ 全部通过」⇒ **两套 harness 一律串行**、timeout **≥ 900 s**；跑完**拿逐套数字跟 `README` §7 表对一遍**。⚠ **管道之后的 `$?` 是 `tail` 的退出码** ⇒ 要量被测进程就**分开跑**。**量错了对象 = 没量。**
- ⚠ **Chrome 层导航超时 / 报「`NOT FOUND` 锚点变了」时，先量网络、先去产品里 `grep` 那个锚点，别先怀疑产品** —— 主页一条 `@import` 拉 Google Fonts（24 个 `.woff2`，一个请求约 4 s）⇒ 超时**假红**而页面完全正常。判回归：**拿改动前的副本跑同一个 harness**，两边都卡 = 环境。已抽 `NAV_LOAD_TIMEOUT = 60000`。⚠ **探针收尾 `kill()` 在前、删 profile 在后**，句柄挂**模块作用域**（`.finally()` 回调**看不见** async IIFE 里的 `const`，`catch{}` 吞的是 `ReferenceError`，**长得跟「清理成功」一样**）。
