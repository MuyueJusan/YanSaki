## 一、需求（用户原话）

> 请在角色卡编写器中增加一个项目，【人设生成器】，用户输入设定或者要求，ai根据输入内容，生成人设，
> 生成的人设依据模板，用户可以自行设定，也可以使用默认模板，默认模板如下：
> 基本信息: / 姓名: / … / 补充：

拆开是三件事：**① 用户写一句设定 → ② AI 按模板逐项填 → ③ 模板可自定义、也可用默认**。

## 二、插在哪儿、叫什么

`ST_TABS` 里插在 `desc`（角色描述）**之后**。理由：它是「写角色描述」的邻居，产出的东西也正是
`card.description` —— 放在第 4 位，用户从「角色描述」往右一眼就看见。

插完之后：**14 → 15 个选项卡**，`code` 从第 13 个变第 14 个（外部 harness 的 P69 和视觉层
就吃在这上面，见 §七）。

## 三、三个设计决定（写进代码注释了）

1. **模板存浏览器本地**（`localStorage` 键 `stPersonaTpl`），**不写进卡**。
   同 AI 配置那条理由：它是**用户自己的偏好**，不是角色卡的一部分。
2. **生成结果不自动进卡。** 先落进 `stEditor.personaOut`，面板上给你看、**可以直接手改**，
   点「写入」才进角色描述 —— 「生成的东西必须先能反悔」，跟第 9 轮「AI 生成预制块」同一条规矩。
3. **覆盖非空角色描述前弹 `confirm`。** 这是这一族里**唯一不可逆**的动作，不能静默做。
   追加那条路不用问（它不破坏已有内容）。

## 四、写套件时逼出来的那个真 bug（本轮最有价值的一条）

面板上写着「**清空 = 回到默认模板**」，而当时的实现是：

| 位置 | 行为 | 判定 |
|---|---|---|
| `stPersonaTplSet('')` | 内存设成 `''` + `localStorage` **删键** | ✅ 这半边是对的 |
| `stPersonaTpl()` | `typeof stEditor.personaTpl === 'string'` 成立 ⇒ **把空串原样返回** | ❌ |

于是清空之后，面板上**同时出现三种互相矛盾的说法**：

- 标签写「模板（默认）」—— 因为它问的是 `localStorage`（键已删 ⇒ 默认）
- 框里是**空的** —— 因为 `stPanePersona` 拿 `stPersonaTpl()` 的值渲染
- 点「生成人设」报「**模板是空的**」—— 因为 `stPersonaRun` 拿到的也是空串

修法：`stPersonaTpl()` 在内存值是空串时**也回落默认**：

```js
return stEditor.personaTpl.trim() ? stEditor.personaTpl : ST_PERSONA_TPL_DEFAULT;
```

⚠ **这条是写断言时逼出来的。** 要断言「清空 = 回到默认」，就得先把这句话的**准确定义**想清楚 ——
「回到默认」到底是「存储回到默认」还是「显示回到默认」还是「生成时用默认」？
三个都写清楚之后才发现原实现只做到了第一个。

⇒ 这正是 `RULES.md` 六里那句「**断言的方向本身就是需求**」的又一例。
`_reverse13.js` 的 **R1** 就是把这个 bug 按回去，盯着这两条断言。

## 五、模板识别的两个坑

### 5.1 冒号半角 / 全角混着用

用户给的那份模板**本来就是混的**：`姓名:` 半角、`三围：` 全角、`- 风格：` 全角带前缀。
识别必须是 `/^[\s\-]*([^:：\n]{1,12})[:：]\s*$/`。

只认半角会**静默少认 9 项**（三围 / 气味 / 校园·工作的日常装 / 风格 / 标志性穿着 / 配饰习惯 /
泳装 / 内衣 / 补充），而**面板照样渲染、生成照样成功、提示照样打 ✅** —— 只有
「项数**独立算一遍**」抓得住。

⚠ 套件里那个「独立算一遍」是**换一种写法**重算的（剥掉行首 `- `、看行尾是不是冒号），
**没有抄产品那个正则** —— 抄正则的话，正则写错时两边一起错。
`_reverse13.js` 的 **R4** 就是这一针。

### 5.2 字段要按名字去重

`风格` / `标志性穿着` / `配饰习惯` 在**三种装束**下各出现一次 ⇒ **42 行 → 36 项**。
数出来的是「**字段数**」，不是行数。面板上写「N 项」，用户拿它对的是「我写了几个格子」。

## 六、围栏清洗只做一种

模型偶尔把整份东西包进 ` ``` ` 围栏。**只洗这一种**：

```js
const fence = s.match(/^```[a-zA-Z]*\n([\s\S]*?)\n?```$/);
if (fence) s = fence[1].trim();
```

⚠ 再多的「智能」清洗（比如顺手删掉开头那句「好的，这是人设：」）会**吃掉真正的第一行**，
而那种错**看不出来**：输出照样有内容、照样能写进卡、用户照样会点写入。
⇒ 套件里必须配「**没包围栏的不许动**」作对照（`_reverse13.js` R3 的 green 名单里就有它）。

### 8.1 第一版红的 7 条，全是**测试自己写错**

| 红的是 | 真因 |
|---|---|
| 「项数跟独立算出来的一致」 | **数组用 `===` 比** —— 引用相等，内容一样也永远不等 |

## 十四、数量不变，所以「跟数量绑定」的断言一条都不用改

先分清两类：

- **跟数量绑定**：`ST_TABS.length === 15`、`#st-tabs .st-tab` 数 15、折叠后 15 个标签、
  `smoke.js` 的「15 个选项卡逐个切」、`st-ai.js` 的「选项卡数量变成 15」…… **全都不用动**。
- **跟顺序绑定**：会来收账。产品里 `ST_TABS` 一处；套件里 4 处。

## 十五、顺序型断言有三种长相，两种**根本不会红**（本轮最有价值的一条）

| 长相 | 在哪 | 会不会红 |
|---|---|---|
| ① 遍历清单是**字面量数组** | `verify_tavern_visual.js` 的 `[[id, marker], …]` | ❌ **不会红** —— 新项不在里面，只是静默少走一页 |
| ② **子串正则** | `st-code.js` 的 `/sb,code,export/` | ❌ **不会红** |
| ③ **相邻距离写死** | `persona-verify.js` 的 `pi - di === 1` | ✅ 会红 |

② 是这一轮抓到的：`ST_TABS.map(t => t.id).join(',')` 变成
`…,sb,code,persona,export,…` 之后，`/sb,code,export/` **照样匹配** ——
子串 `sb,code` 还在，正则跑到 `export` 就不再看后面。**它没红，只是把 `persona` 从覆盖里静默漏掉。**

⇒ 改法：把整段列全（`/sb,code,persona,export/`），并把断言名改成
「code 排在 sb 和 export 之间、**persona 紧跟其后**」—— 名字里写明现在盯的是什么，
下次再挪**光看名字就知道该改哪条**。
⇒ 教训：**顺序型断言别写成「子串在不在」**。要么列全，要么用相邻距离。

## 十六、③ 会红，但光改数字不够 —— 要补对照组

`pi - di === 1` → `pi - ci === 1`（`ci` = `code` 的下标）。**再加一条反向对照**：
「它**不再**跟在「角色描述」后面」（`pi - di !== 1`）。

理由：正断言只要求「挨着 `code`」，**不要求「离开 `desc`」** —— 位置其实没挪动也能让它绿。

⚠ 这条对照**第一版我自己写错了**，套件当场抓住：`check(name, actual, pred, expect)` **只收 4 个参数**，
我按正断言的形状写成 5 个（`pi - di, 1, v => v !== 1, '≠1'`）⇒ `pred` 成了字面量 `1`，判 `11 === 1` → 红。
**函数谓词只占一个位置，后面只剩一个「给人看的期望值」。**
（这是套件在**帮我**，不是在坏 —— 那条对照组确实值得存在。）

**一份镜像文件 ↔ 一个技能目录** ⇒ 手动 `cp` 很容易装错地方、或者**装反方向**（把镜像当源，覆盖掉本地）。这才是「跨设备」真正卡住的地方。

1. **默认 dry-run** —— 不加 `--go` 只打印计划。
2. **默认不覆盖** —— 已存在且内容不同就**跳过 + 提示**，要覆盖得显式 `--force`。**这是故意的**：记忆的真相源是**本地**，在**写这份记忆的那台机器**上跑，覆盖 = 把新内容冲掉。
3. **绝不碰 `.workbuddy-ai/git/credentials`** —— 那个文件在 gitignore 里，脚本里也一个字都没提它。

## 二十八、改动推上去了、但**线上没变** —— 三条 workflow 抢一个 `pages` 并发组

第十二轮的收尾（也就是上面那一节）在推送这一步卡住：`4002051` 推成功、远端 11/11 blob 一致，**但线上还是旧版**。

### 现象

```
static.yml  completed/success    61d09f5  07:52:18Z → 07:53:16Z
static.yml  completed/cancelled  68e9d84  07:57:58Z → 07:57:59Z   ← 1 秒
static.yml  completed/cancelled  4002051  08:20:54Z → 08:20:55Z   ← 1 秒
线上 index.html: 200  1 487 774 字节  sha1 ecb46ca8de99…（= 61d09f5 那版，旧）
本地 index.html:      1 493 542 字节  sha1 d0bf0d34afef…
```

### 判据：**cancelled 且「一条 job 都没有」= job 从没被调度**

```
GET /actions/runs/<id>/jobs  →  { total_count: 0, jobs: [] }
```

成功那几次都有 `job: deploy` + 7 个 step；被取消那两次**一条 job 都没有**。所以**不是构建失败**，是 run 在**排队阶段**就被掐了。
再加 `updated_at - created_at ≈ 1 秒`，基本可以直接指向**并发组**。

⚠ 另一条更硬的判据：`GET /repos/<o>/<r>/deployments` —— **排队阶段被取消的 run 根本不会创建 deployment**。所以 `/deployments` 里最新那条还是 `61d09f5`。这比看 run 列表更权威。

### 根因：三条 workflow，同一个 `concurrency: group: "pages"`

```
active  Deploy Hugo site to Pages                                  .github/workflows/hugo.yml
active  Deploy Jekyll with GitHub Pages dependencies preinstalled  .github/workflows/jekyll-gh-pages.yml
active  Deploy static content to Pages                             .github/workflows/static.yml
```

三条**全部** `on: push: branches: ["main"]`，**全部** `concurrency: { group: "pages", cancel-in-progress: false }`。

GitHub 的并发组语义：**新进入同一组的 run 会取消「已经在排队（pending）」的那个**（`cancel-in-progress: false` 只保证不打断**正在跑**的）。三条同时被 push 触发 ⇒ **互相取消**，谁恰好在 pending 谁死。`hugo.yml` / `jekyll-gh-pages.yml` 是 GitHub **自动塞进来的模板**，这项目根本没有 Hugo/Jekyll 站点 ⇒ 它们的 `build` 每次都失败（`hugo.yml` 战绩 0 成 9 败）。

**旁证**：同一 commit 的 `check-runs` 里会多出**别条 workflow 的** `build : completed/failure`：

```js
GET /repos/<o>/<r>/commits/<sha>/check-runs
→ build : completed/failure   （hugo / jekyll 的，跟 static.yml 无关）
```

### 我自己踩的两个坑（都在「取令牌」这一步）

1. ⚠ **`sed` 分隔符跟字符类撞了**：`s@…\([^@]*\)@…@` —— `@` 既是分隔符又在 `[^@]` 里，直接报 `unknown option to 's'`。换成 `#` 那版又报别的。**不跟它耗**。
2. ⚠⚠ **`node -e '…' TOK="$TOK"` 把变量传成了「脚本参数」，不是环境变量** ⇒ 脚本里 `process.env.TOK` 是 `undefined` ⇒ 请求 401。正确写法是**前置**：`TOK="$TOK" node -e '…'`。

**最终做法（推荐）**：**在 Node 里读凭据文件、在 Node 里发请求** —— 没有 shell 引号问题、没有 `sed` 方言问题、也**不可能把令牌打进终端**：

```js
const line = fs.readFileSync(credPath, 'utf8').split(/\r?\n/).find(l => l.trim());
const TOKEN = line.match(/^https:\/\/[^:]+:([^@]+)@/)[1];   // 永远不打印 TOKEN
```

3. ⚠ **`GET /pages` 不带令牌返回 404 —— 公开仓库的健康 Pages 也是 404**。我一度拿它当「Pages 配置丢了」的证据，是**自己造的假线索**。带令牌同一个仓库读出来是：

```
status=null  build_type=workflow  cname=yansaki.top  html_url=https://yansaki.top/
source={"branch":"main","path":"/"}  https_enforced=true
```

**Pages 配置一直是好的**，坏的只是「谁来部署」。

```js

```

- ⚠⚠ **`git push` 绿了 ≠ 上线了**。「远端 blob 一致」只证明**仓库**对了，不证明**站点**对了。要拿**线上字节的 sha1** 跟本地文件比。已写进技能 Checklist。
- ⚠ **「cancelled + 零 job」和「failure」是两种完全不同的病**，判据在 `GET .../jobs` 的 `total_count` 上。看到 `cancelled` 先去数 job。
- ⚠ **先怀疑自己造的假线索**：无令牌 `GET /pages` 的 404 是我自己不看认证状态得来的，白绕了一圈。

### 收尾时撞上的第二件事：代理把 `git push` 挡死了 —— 改用 **Git Data API 兜底推送**

停用 workflow 那一提交推完之后，再推 `b52a4f8`（deploy-check 的对齐小修）时：

```
git push origin main          → CONNECT tunnel failed, response 502   （连续 11 次 / 跨 4 分钟全败）
env -u proxy git push         → Could not connect to github.com:443   （直连根本不通）
node fetch api.github.com     → ✅ 778ms                              （直连是通的！）
```

**关键观察**：**Node 的 `fetch` 不走 `http_proxy`** ⇒ 它直连，而 `api.github.com` 直连可用；
`git` 走代理，而代理对 `github.com` 的 CONNECT 一直 502。**同一个网络，两条路，一条死一条活。**

⇒ 用 **Git Data API** 把那个 commit 推上去。**核心手法：复刻一模一样的 commit 元数据**
（tree / parent / author / committer / message 全从本地 `git cat-file commit` 原样取出）
⇒ **远端算出来的 sha 等于本地 sha** ⇒ **零分叉**。

实测三个 sha **全中**：

```
本地: commit b52a4f83…  tree f4ababa8…  blob 4fabdf25…  parent 8ffffa3b…  author 1790158678 +0800
远端: 建 blob  → 4fabdf25…  ✅
      建 tree  → f4ababa8…  ✅
      建 commit → b52a4f83…  ✅（与本地逐字节同 sha）
      移动 ref → refs/heads/main = b52a4f83…  ✅
⇒ ✅ 远端 = 本地 = b52a4f83f655919b333a88074264721df10610fb，**同 sha、零分叉**
⇒ 而且照样触发了部署：static.yml 10:24:40Z completed/success
```

⚠ **闸门设计**：每一步都拿本地 `git rev-parse` 的 sha 比，**任何一步对不上就立刻退出** ——
此时远端 ref **一个字节都没动**（`create blob/tree/commit` 都不会移动 ref），只会留下几个
dangling 对象。**最后一步 `force: false`**，非快进让 GitHub 自己拒掉。**这就是它敢试的原因。**

⚠ 三个容易翻车的细节：
- **message 必须逐字节一致、含结尾换行** ⇒ 读原始 commit 对象按**第一个**空行切，别用 `-p` + `trim`；
- **日期**：Git 存的是 `<epoch> <+HHMM>`，API 要 ISO 8601 ⇒ 要**从 epoch + 存下来的 offset 反推**，
  否则 offset 不往返、sha 就不等（实测 `1790158678 +0800` → `2026-09-23T18:17:58+08:00`）；
- **改动的路径**用 `git diff-tree -r --no-renames --name-status -z <parent> <sha>` 取，
  `--no-renames` 把 `R100 old new` 拆成 `A`/`D` 一对，解析就简单了；删除项在 tree 里传 `sha: null`。

**固化成常驻工具**：`_verify/api-push.js`（⚠ **默认 dry-run**，`--go` 才真推；能连推一串 pending commit）。
已登记进 `run-all.js` 的 `NOT_A_SUITE`。⚠ 写它的时候自己踩了个**会卡死**的 bug：
留了一行 `git hash-object --stdin` —— 那会**等 stdin**，跑起来就是无限挂起。已删。

⚠ **又一次印证「默认不写」的原则**：会写远端的脚本，默认动作必须是**只读**。
（同 `_purge-tmp.js` 默认只数、`setup-dev.sh` 默认 dry-run、以及这次的「停用 > 删除」。）

| 写法 | 样本 | 出现在 |
|---|---|---|
| 中文数字 + 、 | `## 一、时钟卡片` … `## 二十一、测试` | `01`–`06` / `04-card-editor` / `RULES` / 当日日志 |

### ⚠⚠ 第一版把**判据范围**定错了，一次报出 24 处假撞号

第一版按「**同一文件、同一层**」比。跑出来：

```

CHANGELOG.md    ❌ 撞号 [H3 / cir / ①] 共 27 处 …

```

—— 全是假的。日报和 CHANGELOG 的每个 `## 第 N 段` **各自有 `### ①…⑧`**，
那是**每段内部的局部编号**，跨段重复完全正常。

**正确的范围是「同一个父节内」**（按标题栈找最近的上级标题，`##` 的父节是文件根）。
改完 ⇒ **0 撞号 / 0 软提示**。

⚠ **教训：「判据范围定错」是一种独立的失败形态，而且它长得像「工具很严格」。**
假红比不检查更坏 —— **它会让人开始无视这个工具**（跟「永远在报的检查」同一个下场）。
⇒ **写范围型判据时，先问一句「这个范围里，重复到底该不该算错」**，
并**拿真实文档跑一遍看红的是不是真问题** —— 如果一次报 24 个，先怀疑判据，别先怀疑文档。

    const t = String(text == null ? '' : text).replace(/\r\n?/g, '\n');
    const m = t.match(/^[ \t\-*]*姓名[ \t]*[:：][ \t]*(.*)$/m);

### ② 两个坑

- ⚠⚠ **CRLF 又来了，这次是从「运行时数据」进来的。** JS 的 `.` **不匹配 `\r`**，
  多行模式下 `$` 也不认 `\r` ⇒ `姓名: 艾莉丝\r\n年龄: 19` 会**整行匹配不上**，
  症状是「名字悄悄取不到、回落成卡名」。所以函数**第一步就归一 CRLF**。
  以前那条规律说的是「源文件是 CRLF」，这回是**生成结果 / 用户粘进来的文本**也可能是 CRLF ——
  **凡是 `$` 锚行尾的正则，都要问「喂进来的这个字符串会不会带 `\r`」。**
- ⚠⚠ **「回落」是一种把失败伪装成成功的设计。** 取不到「姓名:」就退回卡名 ——
  条目照样建好、正文照样对、提示照样 `ok`，**只有名字悄悄变成了卡名**。
  ⇒ 所以回落**必须在提示里说出来**（「生成结果里没有「姓名:」，用的是卡名」）。
  这跟第十四轮那条「报不会变的数的提示天然为真」是一族：**成功信号本身不构成证据。**

### ③ 验证：一对「天然成立的对照组」被拆开

⚠⚠ **这一轮最值钱的发现**：套件里 `OK_REPLY = '姓名: 夜乃\n年龄: 19\n性别: 女'`，
而卡名也设成 `夜乃` —— 于是「取的是 `姓名:`」和「取的是卡名」**读出来是同一个字符串**，
断言**根本分不出它从哪儿取的**。哪怕把取值函数整个删掉，那两条也会绿。

修法：另起 `BOOK_REPLY = '姓名: 艾莉丝\n年龄: 19\n性别: 女'`，卡名保持 `夜乃`。
期望值「艾莉丝」**不是**卡名，这一条才真的在证来源。

⇒ **写「从 A 取」这类断言之前，先问：A 和 B 的值会不会碰巧一样？**
一样的话这一条是恒真的。**对照组要「不同」，不只是「存在」。**
