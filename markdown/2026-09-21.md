## 状态栏新增「预制块」：用块库的原子块拼好的一整组

用户原话：
> 为角色卡编写器内【状态栏】添加使用块库内的资源组合的【预制块】，要求覆盖常用常见的，
> 比如生命值，物品栏，npc好感度（单个和复数），以及能够让用户生成新的【预制块】
> （生成的预制块保存在用户本地）

### 背景：中间那层是空的

状态栏那边原来只有**两层**入口 —— 版式模板（6 个，**整张画布换掉**）和块库（9 个原子块，
**加一个**）。缺的是中间那层：「往里加**一整组**」。这次补上，变成四层：

| 入口 | 数量 | 点一下 | 放哪 |
|---|---|---|---|
| 版式模板 `ST_SB_TEMPLATES` | 6 | **整张换掉**（带 confirm） | 状态栏页顶部 |
| **预制块 `ST_SB_PREFABS`** | **16** | **加一整组**（多块 + 分组） | 图层下方 |
| 块库 `ST_SB_BLOCKS` | 9 | 加**一个**原子块 | 预制块下方 |
| **我的预制块** | 用户攒 | 加用户存的那一组 | 预制块区末尾 |

⚠ **这四个东西长得像、语义完全不同** —— 先把这个对照表写进文档，否则用户（和以后的我）
一定会把「预制块」当成「又一个模板」。

### 16 个内置预制块（5 分类，源码枚举）

| 分类 | 预制块 |
|---|---|
| 生命与属性 | `hp` 生命值 · `hpmp` 生命+魔力 · `attr3` 三项属性 · `level` 等级与经验 |
| 物品与经济 | `bag` 物品栏 · `bagslots` 物品栏（三格） · `money` 金钱与阶段 |
| 关系 | `affdots` 好感度（星级） · `affbar` 好感度（进度条） · `affcard` 好感度（完整） · `affmany` 好感度（多人·竖排） · `affmanyrow` 好感度（多人·横排） |
| 世界与剧情 | `world` 时间与地点 · `hero` 主角状态 |
| 通用 | `head` 标题+分割线 · `kvrow` 两列数值 |

每项是 `{ id, icon, name, cat, hint, build(v) }`。`build(v)` 拿一个**变量绑定 API** 现场拼块，
`v` 提供 `blk / row / bind / many / free`；**每次插入新建一个 `v`**（内含 `used` 表 +
`auto`/`total` 计数），**不是全局单例** —— 否则连续插两次，第二次的「用了哪些变量」是脏的。

### 变量绑定：三条铁律

1. **变量自己的 `min`/`max` 优先**（同 `stSbAutoPick` 的理由：作者设过 0~5 的条不能被压成 0~100）。
2. **`extra` 盖不掉 `bind`** ⇒ `blk` 里顺序必须**先 extra、后 bind**。
3. **复数不能循环调 N 次单绑** —— `used` 表只挡「同一条路径」，三个槽会**全绑同一个变量还不报错**。
   必须走 `stSbPrefabBindMany`，按树序捞 N 个不同的。

绑不上时**不留「未选变量」的坑**，写兜底路径（后续建同名变量即通），但**当面提示**：
`stSbPrefabNote` 用 `warn` 说清「几个绑上了、几个还是默认路径」。

### 用户自己攒的（「保存在用户本地」）

`localStorage['stSbPrefabs']` = `{ v: 1, list: [...] }`，**跨卡共用、不进草稿**。

存（拿选中的块/整组深拷贝）· 同名**覆盖 + confirm**（单入口，少一处歧义）·
插（`stSbCloneBlocks`：深拷贝 + 过白名单 + **整树换新 id**）· 删（confirm）·
闸门（单条 40 KB / 总计 160 KB / 最多 60 条，**写失败必须说出去**）·
容错（读时逐条 try，**坏数据跳过不炸整份**）。

### 两个真 bug（都是套件抓出来的，不是我读出来的）

**① `extra` 里的 `max: 5` 盖掉了绑到的变量范围**

星级预制块的 `extra` 带着 `max: 5`（本来是给兜底路径准备的），而 `blk` 里 `extra` 是**后**应用的
⇒ 卡里 0~100 的好感度被压成 0~5，值 50 直接顶满，**五颗星永远全亮**。

修：`blk` 改成**先 extra、后 bind**；三处 `dots` 的 `extra` 删掉 `max: 5`；
套件加一条**专钉这个顺序**的断言（`⚠ extra 里的 max 盖不掉绑到的范围`）。

**② 「全是垃圾」的用户预制块变成一份装着空块的幽灵**

`stSbBlockFromRaw('不是对象')` 是**宽容**的 —— 返回一个**空白块**。于是读一份全是垃圾的
`list` 时，每条垃圾都变成一个「装着两个空文字块」的条目，**留在列表里而且名字看着正常**。
判据 `坏数据被逐条跳过，不炸` 抓到（`actual="好的一份,垃圾块"`）。

修：两处（`stSbUserPrefabs` / `stSbCloneBlocks`）都先卡
`if (!b || typeof b !== 'object' || Array.isArray(b)) return;` —— 并写清理由：
**草稿解析那儿要宽容（半截卡也得能打开），这儿不能宽容。**

## 续：让 AI 生成预制块

用户原话：
> 能否增加由ai生成新的预制块？

在上一段「手动攒预制块」旁边再开一条路：**写一句中文，让模型拼好一组**。

### 三个设计决定

1. **只要块，不要 HTML。** 模型回 `{ name, icon, blocks: [...] }`，每块过 `stSbBlockFromRaw`
   那份白名单（跟「自己攒」同一套字段口径）。不让它回一整段 HTML —— 那等于把
   「解析别人的手写状态栏」那条最难的路再走一遍，而且整段 HTML 没法过字段白名单。
2. **把卡里真实的变量路径喂进提示词**（`stSbVarPaths()` 前 80 条：路径 + 类型 + 范围）。
   不喂的话它会编 `stat_data.生命值`，而卡里那个叫 `hp` ⇒ 生成出来全是死路径。
   卡里还没建变量时明说一句，让它自己起 `stat_data.xxx`。
3. **不覆盖同名的**（`stSbAiUniqueName`：`战斗面板` → `战斗面板 2`）。
   AI 生成是异步的，弹 confirm 问「要覆盖吗」很别扭；静默覆盖别人的东西更糟。

**生成的结果不直接进画布** —— 先落进「我的预制块」，再点一下才进画布。
**生成的东西必须先能反悔。**

整条链**复用**编写器已有的 AI 调用（`stAiCfg` / `stAiReady` / `stAiChat` / `stAiJsonOf` /
`stAiErrText`），**没有另起一套配置或请求**。`stream: false` —— 要的是 JSON，边吐边解析没意义。

### 清洗：模型不许碰「保原样」那几组字段

`stSbAiClean` 在白名单之外，把 `offX/offY/w/h`、`extra/extraInner/extraFill/wrapExtra`、
`clsMap/clsOwn`（7 层 class 映射）一律归零。它们存在的意义是
「解析别人的手写状态栏时别动原作者写的东西」，而这里生成的是**全新的块** ——
模型瞎猜一个偏移只会把外观锁死。递归，`row` 里的子块一样过。

### 两个真 bug（第九轮套件 G 段抓出来的）

| # | 现象 | 根因 | 修 |
|---|---|---|---|
| ① | **深度上限形同虚设** | 只判了块数（`if (count.n > 24)`）—— 一棵「5 块、深 5 层」的树两个数都没超 24，裁剪根本没跑 | `n > MAX_BLOCKS \|\| deep > MAX_DEEP`，**两个上限各自独立** |
| ② | 超深时「AI 生成失败」，而用户明明给了内容 | 按深度**砍掉子树** ⇒ `row>row>row>row>文字` 砍完只剩三个空 `row` ⇒ 被判「空块」整份拒收 | 改成**摊平**（子块提到同一层）。**丢层级可以，丢内容不行。** 提示词补第 8 条 |

② 的现场是 `actual=0`，看着像「裁剪写错了」，其实是**裁剪把内容裁没了** ——
「数字不对」和「东西丢了」是两回事，先问「这棵树本来该剩几块」。

### ⚠ 这一轮学到的

**① 反向测试多一道闸门：探针点名的断言必须在基线里真的存在。**

第一版**第一次跑就抓到 4 处**，其中一处特别值得记 ——

- **`green`（对照组）名单里放一个不存在的断言名** ⇒「对照组一条都没红」**天然成立**：
  **对照组被悄悄削弱了，而探针照样全绿**。
  （`red` 里放不存在的名字会红得很吵，`green` 里放不存在的名字**安静得要命**。）
- 另外 3 处是断言名**带前导空格**（`check('  是摊平不是砍掉…')`）：`check()` 打的是
  `  ✅ ` + 名字，抽 ✅ 用的正则 `^\s*✅\s+(.*)$` 里的 `\s+` 会把名字**自己的**前导空格
  一起吃进去 ⇒ 抽出来的名字少了两个空格，而名单里手抄的是带空格的原文 ⇒ `indexOf` 永远 -1。
  **两边都 `trim` 才是同一个名字。**
- ⇒ 名单对不上就**直接退出**，别浪费后面 4 次整跑（每次约 40 s）。

**② 失败项的列表符两套件不一样。**

（跟「汇总行两种格式」是同一类病：**格式差异不报错，只安静地少看一半。**）

**③ 三处是测试自己写错，不是产品错**（跟上一段同一条教训）

## 第三段：把「复古线框战机」搬进小游戏弹窗

### 需求

选机页 / HUD / 暂停页 / 结算页 / 3 种 Boss。要求是「像其他的小游戏一样」⇒ 走现成那条路：
`openCatGame()` → `#gameMenuList` 菜单项 → `launchGame(type)`。

### 路线：iframe + `srcdoc`，整份内联

先量了一下：`saki.html` 对外**零个本地相对引用**（只有 Google Fonts + Discord 两个远程 URL）。
⇒ **外链会毁掉「双击就能跑的单文件」这条立身之本**，所以不能放成 `saki-shooter.html` 那样的外部文件；
重写又是另一回事。剩下唯一的路：**把整份源码当常量塞进 `<script>`，喂给 `<iframe srcdoc>`**。

`srcdoc` 而不是 `src`：不发额外请求、不受 `file://` fetch 拦截影响；`srcdoc` iframe **继承父页面源**
⇒ 同源可达，套件能进去求值。iframe 是**独立文档** ⇒ 它的 `id` / `class` / 全局变量**一个都不会漏到主页**。

常量放 `<script>` 的**最末尾**（`26378` BEGIN ~ `28738` END，字面量跨 2 354 行）——
这样上面所有行号锚点**一个都不动**。

### 五条转义规则（要同时满足 JS 和 HTML 两个解析器）

| 规则 | 不转义会怎样 |
|---|---|
| `\` → `\\` | **最要命**：`/\d+/` **静默**变 `/d+/` —— 游戏能开、正则全废、什么都不报 |
| `` ` `` → `` \` `` | 模板字面量提前闭合 |
| `${` → `\${` | 当成插值（通常硬报错，偶尔静默 `undefined`） |
| `</script` → `<\/script` | 外层 `<script>` 被**提前掐断** |
| `<!--` → `<\!--` | HTML 词法器进 **script-data-escaped** 态，此后 `</script` **不再算结束标签** |

最后一条只在「源文件恰好凑齐那个序列」时才咬人。这份文件**正好凑齐了**：
`<script src=tailwind>` 第 7 行 → `<!--` 第 129 行 → 主 `<script>` 第 329 行。
`\/` `\!` 都是 JS 的 `NonEscapeCharacter` ⇒ **运行时字符串跟原文一字不差**。

**行尾**：磁盘上是 CRLF（跟 `saki.html` 统一），但 JS 规范要求模板字面量把 `<CR><LF>` **规范化成 `<LF>`**
⇒ 运行时那份是**纯 LF**。两边都对 —— 所以判据必须写清「比的是哪一份」。

### 判据 = 往返逐字节，不是「能跑起来」

```js
vm.runInNewContext('`' + escaped + '`') === source.replace(/\r\n/g, '\n')
```

「游戏能启动」在 `/\d+/` 坏掉时**照样过**。往返自检**第一跑就逮住生成器自己两个真 bug**：

- 转义多吐一个字符：`out += '<\\/'` 顺手把 `/` 也输出了，循环又输出一次 ⇒ `</script` 变 `<//script`
  （`<!--` 同病）。**不报错，只会让游戏里某个标签悄悄失效。** 修：只补 `<` + `\`。
- 提取器切错刀：从头找第一个 `` `; ``，撞上正文里的 `` radioText.innerText = `📡 ${msg}`; ``
  ⇒ 求值报 `Unexpected end of input`，**看着像文件写坏了，其实是读的人切错了刀**。
  修：从 END 标记**往前**找最后一个 `` `; ``。

写盘守卫也修过：第一版数 `<script` 的个数 ⇒ 字面量里那两条**开标签**本来就该多出来 ⇒ **永远误报**。
改成只数**闭标签** `</script` 和 `<!--`。

⚠ 残留小瑕疵：`saki.html: before → after 字节` 那一行仍用 `.length`（UTF-16 码元）却标「字节」，
中文文件里差 5 KB。`--verify` 路径是准的。

**① 卸载必须摘 DOM，不能只藏。** 那游戏的 `gameLoop` 在 `gameState !== 'PLAYING'` 时**照样**

只调 `f.contentWindow.focus()` **完全无效**：父页面 `activeElement` 还是 `BODY`、

### ⚠ 这一轮学到的

**① 往单文件里内联「一整份外部网页」，判据只能是往返逐字节。**
「能跑起来」在 `/\d+/` 坏掉时照样过；五条转义里 `\` 那条**最静默**。
⚠ **`<!--` 那条要跟 `</script` 一起看** —— HTML 词法器进 escaped 态之后 `</script` 就不再是结束标签了。

**② 卸载要「摘」不要「藏」。** 只要目标里有 `requestAnimationFrame` 自排队（哪怕只在某个状态），
藏起来 = 后台满帧空转。⚠ 判据是**两次读数比较**，一次读数什么都证明不了。

**③ 焦点是「时机」问题，而且它坏起来是隐形的。** 画面完全正常、控制台一声不响、键一个都进不去。
⇒ 这种 bug **只能靠「真发一个键」的断言**抓，靠读代码看不出来。⚠ 断言要配**对照组**（父页面没收到）。

**④ 断言的名字不能取决于运行时分支。** 看着更精确，其实是给反向测试挖坑 ——
`red` 匹配不上时「预期该红的都红了」会因为**一条都没有**而照样打 ✅。⇒ 一个布尔、一个固定名字，
分支用 `console.log` 打出来。

**⑤ 「天然成立」的判据有第三种形态**：`score === 0` 不是「被重置过」的证据
（上一局只跑 1.5 秒，本来就得 0 分）。⇒ 换一个**不可能碰巧等于初值**的量（时长）。

**⑥ 审计工具报 ✅ 只是必要条件。** 新横幅**落在旧锚点的行号上** + 共享两个字
⇒ 硬判据过、软提示不响 ⇒ **17 行全错而工具说全对**。⇒ 改完 CSS 别只看 ✅，手 `grep` 两三个锚点。

**⑦ 内联一段大字符串会往静态检查的「已声明 / 被引用」两边同时灌水。**
自洽 ⇒ 今天不误报，但会**掩盖**「主页同名函数被删」。⇒ 切掉 blob 再查，并**打印切了多少字节**。

**⑧ 「同一个数在两处各算一遍」本身就是一条会静默漂的断言。**
报告里的 `declared` 和判据用的声明集合**各写了一遍正则**（还是不同写法）
⇒ 改一处就漂，报告的数跟判据用的集合对不上，而**两边都不会报错**。
收成 `declaredNamesOf()` / `usedNamesOf()` 两个口径函数，判据与报告都调它；
顺便闸门自己就把「灌了多少水」打出来了（不用另写探针）：

```
内联游戏源码: 切掉 108651 字节；顶层 `function name(` 887 → 860；declared 1020 → 988；used 150 → 146
```

⚠ **这几个数被写错过一次**（记成 1019 → 987 / 886 → 859 / 「27 个顶层函数名」）：
那一版是在 **抽出 `stShooterFocus` 之前**量的 —— 它在 blob **之外**，
所以 `function name(` 与 `declared` 两边各 +1（886→887 / 987→988）。
⇒ 教训跟「行号会静默漂」同源：**工具的输出也是「当时的读数」，重构一次就作废**；
收尾核文档数字时**要重新跑一遍工具**，不能抄上一次的输出。
⚠ 另：**27 与 32 不是同一个量** —— 27 只是 `function name(` 那一条正则的差，
拿它当「declared 灌了多少」会少算 5 个（另 5 个来自 `const x = function|(`）。
