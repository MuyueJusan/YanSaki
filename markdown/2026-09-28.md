## 第二十三轮 · 世界书关键词改成**标签控件**（+ 揪出一句「从来没成立过」的提示语）

### 需求（原话即规格）

>   【标签】，要求每个词被圆角矩形包裹，输入时以回车为一个词，可以对某个关键词直接删除」

### 落地

新增通用小控件 **`stTags(label, path, opts)`**，跟 `stInput` / `stArea` 并排放在「通用小控件」一节；
七个手感函数（`stTagHtml` / `stTagsPaint` / `stTagsFocus` / `stTagsCommit` / `stTagsDel` /
`stTagsKey` / `stTagsPaste`）放在 `stSetListText` 旁边。`stEntryHtml` 里那两个 `stInput` 换成 `stTags`。

- **DOM 形状**：`st-<id>`（输入框）+ `st-<id>-tags`（装标签的框）。
  ⚠ 输入框 id **没换**（还是 `st-e0-keys` / `st-e0-sec`），`label[for]` 照样指得过去。
- **存的还是数组**：走的还是 `ST_TEXT_LIST` 那套 `XxxText → keys` 别名。
  ⇒ `stAfterSet` 里那条定向刷新（`keysText` → `stRefreshEntrySummary`）**一个字没改**就复用了 ——
  它只刷那一行摘要、**不整块重画**，所以光标不会飞。这条有断言盯着节点身份。
- **CSS**：`.st-tags` / `.st-tag` / `.st-tag-x` + `body.retro-mode` 四条。
  ⚠⚠ 输入框那条**必须**写 `.st-field .st-tags-in`（0,2,0）——
  光写 `.st-tags-in`（0,1,0）压不住 `.st-field input`（0,1,1），
  会得到一个有白底有边框的方框塞在圆角框里。retro 下还要再压一层（那里是 0,2,2）。
- **手感**：回车 / 半角逗号 / 全角逗号落词；点 `×` 删指定的那一个；输入框空着按退格删最后一个；
  重复词不再加；**中文输入法组字中的回车不落词**（`ev.isComposing || ev.keyCode === 229`）。

### ⚠⚠ 写套件才发现的：那句「一行一个」**从来没成立过**

按老规矩给「旧行为不能丢」配断言，喂 `'a,b\nc，d'` 期望切成 4 个词，结果读到 `["a","bc","d"]`：

**`<input type="text">` 的 `value` 会被浏览器按 HTML 规范的 value sanitization 抹掉 `\r` / `\n`。**
那个 `\n` 到 `stSplitList` 手上时早就没了 ⇒ `b` 和 `c` 粘成了一个词。

⇒ **旧版占位符写的「一行一个（也支持逗号分隔）」对单行输入框根本不成立**。
只是因为**没人真拿多行文本往那儿粘过**，一直没人发现 ——
「一行一个」这个承诺**没有任何断言看着**。

处置不是改断言，而是**把这条路补上**：加 `onpaste`，含 `[\n,，]` 的接管、按老规则切开一次落进去；
**单个普通词不接管**（留给浏览器原生插入，别抢手感）。新占位符改成
「输入后回车落一个词（逗号也行）」，不再承诺做不到的事。

### 三条可迁移的教训（已进 `RULES.md` 六之五十八 / 六之五十九 + `SKILL.md`）

1. **「设 `value` + 派发事件」这条测试路径，对任何「依赖浏览器怎么处理这个值」的行为都是无效的。**
   单行输入的换行、`<input type=number>` 的非法字符、`maxlength` 截断 —— 全属于这一类：
   测的是**浏览器的 sanitization**，不是产品的逻辑。
   ⇒ 走真会产生那个值的那条路（粘贴 / 拖放 / IME / `beforeinput`），或在解析器那一层单测。
   这轮两条都做了：`stSplitList('x\ny,z，w')` 单测 + 真 `paste` 事件。
2. **合成事件不执行默认动作** ⇒ 「粘一个词之后输入框里有没有它」**量不出来**
   （合成 paste 不会替浏览器插字，产品完全正确也读到空串 = **一条永远为假的断言**）。
   能区分「有没有接管」的只有 **`defaultPrevented`** —— 它由**监听器**决定，跟默认动作无关。
   ⚠ 顺带：`new ClipboardEvent(..., { clipboardData: new DataTransfer() })` 在 Chrome 里可用，
   剪贴板这条路不必上 `Input.dispatchKeyEvent` 那种重家伙。
3. **组字中的回车必须单独测**：`new KeyboardEvent('keydown', { key:'Enter', isComposing:true })`
   能设上这个标志，所以那条守卫**直接可测**。⚠ **必须配正向对照**
   （「退出组字之后回车就落了」），否则一个无条件 `return true` 也能全绿 ——
   等于把真 bug 换成一个「永远不触发」的功能。

**让「又插了一个值」必须被看见一次。**

### 经过

### 这次量到底了（探针 + 负载）

| 观察 | 读数 |

### 改了什么

`sb-verify7.js` 在两处宽度断言**前面**各加一条前置断言

### ⚠⚠ 两条元教训（已进 RULES 六之六十）

1. **「单跑是绿的」只能证明「负载低时窗口短」，证明不了机制。**
   上一轮我写「窗口比一次采样还短 ⇒ 别指望再跑一遍」—— **方向反了**：
   加负载就能稳定复现。⇒ **「复现不了」必须连同「试过哪些加压手段」一起才成立。**
2. **读数可疑时，要换一个「不同机制」的判据，不是在同一个机制里换写法。**
   上一轮全是换写法（轮询条件 / 多帧遍历 / 僵尸帧修剪），都还在 **JS 读数**这一个机制里；
   **截图走的是合成器** —— 另一个机制，一锤定音：读数没骗人，预览**真的是白的**。
   ⚠ 没有这一步，就会把一条**真问题**当成假红消掉（六之二十七那类）。
