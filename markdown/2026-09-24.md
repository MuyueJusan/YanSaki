## 第二十轮 · Vertex「列模型失败」+ 完整模式 Key 藏不住

### 起点（用户实测反馈）

> 「还是有问题，我已经开放代理，但是却还是显示【列模型失败】，
>   以及在 vertex 的完整模式下，key 已经用不到了吧」

两句话各指一个真 bug，**两个都躲过了 147 条全绿的套件**。

### 两个真 bug

**① 「Key 用不到」= 那一格根本没被藏起来。**
`keyF.hidden = true` 一直设着，但 `#apig-key-field` 是 `.ai-field`，
而 `.ai-field { display: flex }` **盖掉**了 `hidden` 属性自带的 `display: none`
（后者来自 UA 样式表，权重更低）⇒ 属性设对了、**屏幕上照样看得见，而且不报任何错**。
⚠ 这个坑**踩过两次**（先 `.apig-vertex-box`，当时逐条补了 `[hidden]`）——
**「逐条补」这个做法本身就是会漏的** ⇒ 收敛成**全局一条**
`[hidden] { display: none !important; }`。判据一律读 **computed `display`**，不读属性。

**② 「列模型失败」= 两处错误叠加。**
(a) 只拼了一条 URL `…/v1/projects/{p}/locations/{l}/publishers/google/models`，
而官方 REST 目录里 **v1 那条资源没有 `list`**（只有 computeTokens / countTokens /
embedContent / generateContent / predict / rawPredict / stream*）⇒ 这个 URL 注定 404。
⇒ 改成**候选 URL 串**（`stAiGeminiModelsUrls`，v1beta1 优先，逐条试并把「试过哪几条」带上）。
(b) `stAiModelIds` 不认 Vertex 的 **`publisherModels`** ⇒ 就算 URL 对了也解析成空列表，
报「没返回任何模型」——**看着像 URL 错，其实是解析错**。

**关键发现**：酒馆（SillyTavern）**根本没有列模型的路由**
（`src/endpoints/google.js` 只有 caption / voice / tts / image / video）
⇒ 这条路是**我们自己加的**，抄不到参照物，所以更需要断言盯着。

**③ 顺带修掉一处「功能等于废掉」**：`apigFetchModels` 漏传 `{ needModel: false }`
⇒ Vertex 下必须先**手打模型名**才能点「获取模型列表」。
`stAiReady(cfg, opts)` 早就支持这个 opts，全局面板那一份没传
—— 同一件事两份实现时，**可选参数只传了一份**，那一侧就静默失效。

## ⚠ 基建事故 · `spawnSync` 在这个环境里全线失效

### 现象

`node run-all.js` 打出来是：

```
18 套，共 **0 通过 / 0 失败**
❌ check.js   —   [无] 0.0s  ← 没有可解析的汇总行
（18 套全部这一行）
```

⚠ **这个输出长得像「18 套套件全坏了」** —— 而真正坏的只是 runner 起不了子进程。
`0.0s` 是唯一线索（**真跑过的套件不可能 0.0s**）。
⚠ 手跑单套 `node check.js` 却是好的 ⇒「单跑绿、整跑全红」这个组合会把人往
「串味 / 竞态」上带，**这次是环境，不是产品**。

### 排查绕了三轮，前两轮结论都是错的

1. **第一轮**：诊断出 `spawnSync` 返回 `EBUSY`，而且
   `spawnSync('where.exe')` / `spawnSync('git')` **也一样** ⇒
   误判成「沙箱只放行一层进程创建」⇒ 绕道写了个 bash 驱动版 `run-all.sh`，并把清单抽成 `suites.js`。
   ⚠ 那一版**能用**，但**根因判断是错的**。
2. **第二轮**：注意到套件自己起 Chrome 用的是**异步 `spawn`**，而它们从来没坏过
   ⇒ 开始怀疑是「同步 vs 异步」，而不是沙箱。
3. **第三轮（决定性）**：写 `_diag-spawn2.js` 同时试两种写法：
   ```
   spawnSync : status=null err=EBUSY
   spawn     : code=0 out=v22.22.2
   ```
   ⇒ **真因是 `spawnSync` / `execFileSync` / `execSync` 这些同步 API 一律 EBUSY，
   异步 `spawn` 完全正常。** 跟沙箱无关。

### 修复

- `run-all.js` 改用**异步 `spawn`**（超时自己 `kill`；`SPAWN-FAIL` 单独报，
  不再和 `NO-SUMMARY` 混成一个样子）⇒ `node run-all.js` 当场恢复。
- `_lint-suites.js` 同样改异步 —— 它之前会**全红假报** `❌ 60/60 个文件语法不过`。
- `suites.js`（清单 + 汇总正则的**单一真相源**）保留，`run-all.js` / `run-all.sh` 共用一份。
- ⚠ **还有 14 个 `_reverse2…17.js` 仍然用 `spawnSync`** ⇒ 现在会假红。
  本轮**没改**（它们针对的是旧功能），已写进 README §7 的现状警告；
  要用就先照 `_reverse18.js` 开头那个 `run()` 改成异步。

### 教训（已进 `RULES.md` 六之四十六）

⚠⚠ **「环境不允许」这个结论，要拿同一件事的另一种写法证伪过再下。**
这里 `spawnSync` 与异步 `spawn` 就是同一件事的两种写法，**只试了一种就下了结论**，
代价是白写一个驱动 + 一条写错的记忆（已改回）。

## 收尾：外部整跑那次 `TIMEOUT` 的最终定论（⚠ 不是产品问题）

外部 8 层整跑（`run-all.js`）跑完，**7 层全绿**（static ✓ / tavern 166 / exclusive 80 /
